## Ключевые решения (не искать заново)

1. **Ядро переносимое**: `components/kernel` — чистый C11, без ESP-IDF. Всё железо за `kernel/port.h` + `kernel/port_task.h`. Порты: `components/port_esp32` (ESP-IDF) и `ports/port_host` (Linux, pthread'ы + отдельный пул «PSRAM» для тестов политики памяти).
2. **Две сборки из одних исходников**: `CMakeLists.txt` верхнего уровня определяет ESP-IDF по `IDF_PATH`, иначе хост-сборка. `make test` / `make sim` / `make bundle`.
3. **Планировщик**: run-очередь на каждый приоритет (ёмкость = TASK_MAX_TASKS), квант времени (SCHED_RR), состояния new/ready/running/sleeping/blocked/zombie, `k_sched_validate()` проверяет инварианты.
4. **kmm** — приоритеты памяти: 1 = ядро/драйверы (внутренняя RAM), 0 = системные утилиты (флаг задачи), −1 = пользователь (PSRAM). При нехватке RAM: приоритет решает, кому RAM, кому PSRAM.
5. **MicroFS** — по дизайну пользователя: DATA/META/INFO, относительная адресация, карта свободных блоков + таблица inode по 16 байт, файлы растут цепочками блоков. Том в памяти для тестов, раздел флеша 5.75 МБ на плате.
6. **Флеш ESP32 умеет только сбрасывать биты** → запись поверх старых данных требует read-modify-erase-write; в адаптере флеша есть кэш сектора (4 КБ) + sync.
7. **ABI**: номера вызовов — контракт (0..19), ширина аргументов = ширина указателя цели (`ksys_arg_t`: 32 бита на ESP32, 64 на хосте). Коды ошибок — числа POSIX (`kernel/errno.h`).
7a. **libc**: `components/libc` — тонкий слой над ABI. Свои имена в бинарнике (`microos_printf`), обычные имена — макросы (чтобы не спорить с newlib). Форматизатор свой (~500 строк), проверяется против системной libc на корпусе.
8. **Тесты — про свойства, не про результат**: корпус `tests/corpus/vectors.txt` (512 настоящих чисел с граничными значениями); проверяется, что одни данные дают один результат при разном разбиении на части (1/3/7/64/512/1024/4096), при разном выравнивании буфера, при разном порядке вызовов.

## Грабли (не повторять)

- **Молчаливая замена в python-скриптах**: `str.replace()` не применился (текст не совпал) — файл был перезаписан без изменений, и баг уехал на устройство (на хосте тесты звали инициализаторы руками и маскировали). **Всегда проверять: assert old in s** и сразу `grep` результата.
- **ESP-IDF 5.3 API**: `esp_timer_create(args, &handle)` (аргументы в этом порядке!), `esp_partition_write(part, off, buf, len)`, `esp_partition_erase_range`, `i2c_master_transmit(dev, buf, len, timeout_ms)` (последний аргумент — таймаут в мс, а не флаг!), `gpio_config(&cfg)` (один конфиг, не массив), `esp_adc` → `adc_oneshot_unit_init_cfg_t` / `adc_cali_line_fitting_config_t` (кривую fitting убрали).
- **Флеш**: erase-сектор ~13 мс, писать поверх не-erased нельзя; partition type 0x40 (свой, «mfs»).
- **Дисплей ST7789V2**: память 240×320, стекло 1.14" (135×240) показывает часть — смещение **x=55, y=40** (подобрал пользователь), его можно менять на лету: `display <x> <y>`. SPI через GPIO-матрицу максимум 26.7 МГц (20 МГц), DMA не читает PSRAM.
- **Стек задачи** 8 КБ; большие буферы (4 КБ) — только статикой.
- **UART**: без `uart_driver_install` консоль только пишет, `fgets` всегда даёт EOF. Сейчас читаем по одному символу через `uart_read_bytes` (эхо по буквам).
- **Бут-лог** пишется в `/log/start.log` (директория `/log`), в консоль идёт только отчёт доктора; паника всегда в консоль.
- `build/` был в истории из-за закомментированного правила в `.gitignore` (исправлено, историю не переписывали).
- **Атрибут `format(printf, N, M)` ломается макросом `printf` из libc** → GCC: «microos_printf не является корректной функцией форматирования». Спасает зарезервированное `__printf__` (в `kernel/log.h`, `kernel/panic.h`, `libc/stdio.h`).
- **newlib объявляет `utoa`** → свои вспомогательные функции библиотеки надо называть иначе (`format_utoa`).
- **Ветки**: `work` = разработка, `main` = только проверенное зелёное. Сейчас обе запушены: `work` = 25decc9 (фазы 3+4), `main` = 0fcccd7 (merge work → main, фазы 3+4 зелёные). Креды теперь работают — `git push` проходит.

## Команды

```bash

make sim           # симулятор на хосте (настоящий шелл)
make idf-build     # прошивка (нужен . ~/esp/esp-idf/export.sh)
make bundle        # обновить bild/ (бинарники для прошивки без исходников)
tools/stream_console.py            # интерактивный диалог с платой
```

Тест на железе: `tools/device-test.sh /dev/ttyACM0` (ожидается `RESULT: PASS`).
Порт платы: `/dev/ttyACM0` (CH9102), доступ открыт пользователем.

## Планы

1. **Процессный ABI**: `fork`/`exec`/`wait` поверх задач. Ограничение FreeRTOS: полноценный `fork` с копированием памяти невозможен → реализовать как «создать задачу с копией контекста/данных» + `exec` = заменить образ задачи. Проверить, что это честно описано в ADR.
2. **libc поверх ABI**: `printf`/`open`/`read`/`write` через вызовы, чтобы шелл ходил через ABI, а не напрямую в VFS.
3. Микрофон (I2S), WiFi + NTP (чтобы RTC перестал быть «no clock»), `/proc/self` с каталогами задач (сделано частично).
