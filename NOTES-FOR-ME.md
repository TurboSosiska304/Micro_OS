## Ключевые решения (не искать заново)

1. **Ядро переносимое**: `components/kernel` — чистый C11, без ESP-IDF. Всё
   железо за `kernel/port.h` + `kernel/port_task.h`. Порты: `components/port_esp32`
   (ESP-IDF) и `ports/port_host` (Linux, pthread'ы + пул «PSRAM» для тестов памяти).
2. **Две сборки из одних исходников**: верхний `CMakeLists.txt` определяет
   ESP-IDF по `IDF_PATH`, иначе хост. `make test` / `make sim` / `make bundle`.
3. **Планировщик**: run-очередь на приоритет (ёмкость TASK_MAX_TASKS), квант
   времени (SCHED_RR), состояния new/ready/running/sleeping/blocked/zombie,
   `k_sched_validate()` проверяет инварианты.
4. **kmm**: приоритеты памяти 1 = ядро/драйверы (внутр. RAM), 0 = системные
   утилиты (флаг задачи), −1 = пользователь (PSRAM); при нехватке RAM приоритет
   решает, кому RAM, кому PSRAM.
5. **MicroFS** по дизайну пользователя: DATA/META/INFO, относительная адресация,
   карта свободных блоков + таблица инодов по 16 байт, файлы растут цепочками
   блоков. Том в памяти для тестов, раздел флеша 5.75 МБ на плате.
6. **Флеш ESP32 умеет только сбрасывать биты** → запись поверх старых данных =
   read-modify-erase-write; в адаптере флеша кэш сектора (4 КБ) + sync.
7. **ABI**: номера вызовов — контракт (0..19), ширина аргументов = ширина
   указателя цели (`ksys_arg_t`: 32 бита на ESP32, 64 на хосте). Коды ошибок —
   числа POSIX (`kernel/errno.h`).
7a. **libc**: `components/libc` — тонкий слой над ABI. Свои имена в бинарнике
   (`microos_printf`), обычные имена — макросы (чтобы не спорить с newlib).
   Форматизатор свой, проверяется против системной libc на корпусе.
7b. **kmm**: слабы для блоков ≤ 512 байт (слоты 16/32/64/128/256/512, слаб 8 КБ),
   большие блоки — напрямую из порта. Приоритет: ядро → внутр. RAM, пользователь
   → PSRAM, резерв 48 КБ.
8. **Тесты — про свойства, не про результат**: корпус `tests/corpus/vectors.txt`
   (512 настоящих чисел с граничными значениями); проверяется, что одни данные
   дают один результат при разном разбиении на части, разном выравнивании буфера,
   разном порядке вызовов.
8a. **WiFi разделён надвое** (ADR 0003): `wifi.c` — переносимое ядро (автомат
   состояний, конфигурация, форматирование), `wifi_esp32.c` — бэкенд ESP-IDF.
   Связь — таблицы `struct wifi_radio` + `struct wifi_storage`, поэтому ядро
   тестируется на хосте. Склейка и команда `wifi` — в `drv_wifi.c`. Префикс
   подсистемы — `wifi_` (как `kshell_`, `mfs_`), не `drv_`.
9. **Конкурентность MFS**: замок `mfs_lock`/`mfs_unlock` в `mfs.c`, берётся во
   всех публичных вызовах. «Сонный» (у ядра нет блокирующих примитивов, спим
   1 мс и смотрим снова), рекурсивный. Позиция/флаги файла живут в самом
   дескрипторе (`VFS_FILE_DATA_SIZE`), не в таблице ФС — две задачи не мешают
   друг другу. Маппинг кодов ошибок MFS→KERR — только в адаптере `mfs_vfs.c`.
10. **Панель — одно целое**: рекурсивный замок вокруг `drv_display_*` (команда,
    данные, окно, пиксели — одна последовательность). Консоль не рисует из
    печатающей задачи: пишет строки, помечает экран устаревшим, задача
    `tft-flush` низкого приоритета перерисовывает ≤10 раз/с.
11. **Политика реконнекта — в ядре, таймер — в порте**: `wifi_reconnect_after_ms()`
    (до 5 попыток, пауза 1→30 с, счётчик не обнуляется самой попыткой) +
    `wifi_reconnect()`; порт делает одноразовый `esp_timer`. Init транзакционный:
    `s_initialised` сразу после `esp_wifi_init`, обработчики — один раз,
    `WIFI_STORAGE_RAM`.

## Грабли (не повторять)

- **Молчаливая замена в python-скриптах**: `str.replace()` не применился (текст
  не совпал) — файл перезаписан без изменений, баг уехал на устройство (на хосте
  тесты звали инициализаторы руками и маскировали). **Всегда assert old in s**
  и сразу `grep` результата.
- **В кириллические тексты подмешиваются иероглифы/англицизмы** (было «рваные
  目录», «время не可信», «Whether работа»). После каждой генерации длинного
  русского текста — `grep -P '[\x{4e00}-\x{9fff}]'` и поиск латиницы в русских
  строках.
- **ESP-IDF 5.3 API**: `esp_timer_create(args, &handle)` (сами args называются
  `esp_timer_create_args_t`, НЕ `esp_timer_args_t`), `esp_partition_write(part,
  off, buf, len)`, `esp_partition_erase_range`, `i2c_master_transmit(dev, buf,
  len, timeout_ms)` (последний аргумент — таймаут в мс, а не флаг!), `gpio_config`
  (один конфиг, не массив), `adc_oneshot` + `adc_cali_line_fitting_config_t`.
- **`esp_timer_init()` вызывать руками не надо**: служба поднимается стартовым
  хуком (линкер его держит, раз кто-то зовёт `esp_timer_create`); ручной вызов
  печатает красную строку в каждый boot-лог.
- **Зависимости IDF**: если в исходник добавлен `esp_timer.h`/`freertos/*.h`, их
  надо прописать в `REQUIRES` компонента, иначе «fatal error: ... No such file».
- **`-Wextra` на ESP32**: добавлен `target_compile_options(${COMPONENT_LIB} ...)`
  в `idf_component_register`-ветке каждого компонента; `-Werror` НЕ ставим (сломал
  бы сборку компонентами IDF).
- **Спинлок ESP32 рекурсивен** на одном ядре (owner+count в `spinlock.h`) и
  работает из ISR → `k_port_enter_critical` = `portENTER_CRITICAL`, а не мьютекс.
- **Флеш**: erase-сектор ~13 мс, писать поверх не-erased нельзя; partition type
  0x40 (свой, «mfs»).
- **Дисплей ST7789V2**: память 240×320, стекло 1.14" (135×240) показывает часть —
  смещение **x=55, y=40**, менять на лету: `display <x> <y>`. SPI через
  GPIO-матрицу максимум 26.7 МГц (20 МГц), DMA не читает PSRAM.
- **Стек задачи** 8 КБ; большие буферы (4 КБ) — только статикой.
- **UART**: без `uart_driver_install` консоль только пишет, `fgets` всегда EOF.
  Читаем по одному символу через `uart_read_bytes` (эхо по буквам).
- **Бут-лог** пишется в `/log/start.log`, в консоль — только отчёт доктора;
  паника всегда в консоль. На хосте паника = `_exit(89)` (код 89 = паника), не
  вечное ожидание.
- **Атрибут `format(printf, N, M)` ломается макросом `printf`** → GCC: «... не
  является корректной функцией форматирования». Спасает зарезервированное
  `__printf__` (в `kernel/log.h`, `kernel/panic.h`, `libc/stdio.h`).
- **newlib объявляет `utoa`** → свои вспомогательные функции библиотеки называть
  иначе (`format_utoa`).
- **PSRAM хоста не переиспользовалась**: освобождённый блок лежал в списке
  свободных с размером 0 → first-fit не выдавал. Исправлено: слияние соседей +
  размер в таблице выданных блоков.
- **`port_host_set_sink` владеет файлом**: закрывает предыдущий при замене. Тест
  самому fclose делать НЕЛЬЗЯ (был double free в `test_log.c`).
- **Тест с падением выполняю в fork-процессе** (`test_boot_failure_aborts`):
  наследуемый замок + `_exit` иначе вешают весь прогон. Тик там останавливался
  до fork, чтобы избежать deadlock по унаследованному замку.
- **WiFi ESP-IDF**: `wifi_ap_record_t.ssid` — `uint8_t[32]` без завершающего нуля
  (копировать через `const char *` — ошибка знака); `esp_wifi_connect()`
  возвращает сразу, результат — событием; `esp_wifi_scan_get_ap_records()` просит
  массив `wifi_ap_record_t`; `esp_wifi_set_config(WIFI_IF_STA, ...)` перед
  `esp_wifi_connect()`.
- **NVS**: там же калибровка радио. Раздел старого формата → `nvs_flash_erase()`
  + `nvs_flash_init()`. Своё пространство имён: `microos` (ключи `wifi_ssid`,
  `wifi_pass`).

## Планы

1. **Процессный ABI**: `fork`/`exec`/`wait` поверх задач. Ограничение FreeRTOS:
   полноценный `fork` с копированием памяти невозможен → «создать задачу с
   копией контекста/данных» + `exec` = заменить образ задачи. Описать в ADR.
2. **NTP + HTTP/MQTT поверх `wifi_get_status()`** — чтобы RTC перестал быть
   «no clock» (заодно снимет `degraded` у `rtc` и `wifi` в отчёте доктора).
3. **Настоящий семафор в ядре** — заменит «сонный» замок MFS на дешёвый
   примитив; отдельная работа в обоих портах + ADR.
4. **dup2, защита памяти задач**, `/proc/self` (частично сделано).
