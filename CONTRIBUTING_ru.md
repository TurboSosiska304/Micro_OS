# Участие в разработке Micro OS

> English version: [CONTRIBUTING.md](CONTRIBUTING.md)

Спасибо, что хотите поучаствовать. Ядро пишется аккуратно и по правилам, которые
работают и для человека, и для автопроверок.

## Сборка перед коммитом

```bash
make test      # обязательно: юнит-тесты должны проходить
make format    # привести код к стилю (clang-format)
```

Перед пушем:

```bash
make ci        # сборка, тесты, smoke-тест и проверка целостности
```

`make ci` — список проверок перед пушем: сборка, юнит-тесты, smoke-тест
симулятора и проверка целостности репозитория — объекты git, гигиена
исходников и их форматирование. Workflow'ы облака повторяют этот список на
каждом пуше в `mainline` и `release_candidate` (и добавляют valgrind и
сборку прошивки), так что пуш проверяется там ещё раз. Проверка пакета в
`dist/` подключается, когда собрана прошивка (`make bundle`), а в облаке —
в job'е, который её собрал.

Если менялся ESP32-порт — дополнительно:

```bash
make idf-build
```

## Стиль кода

* C11, без C++ и без GNU-расширений в переносимом ядре (`components/kernel`).
* 4 пробела, максимальная длина строки — 100 символов.
* `-Wall -Wextra -Werror` включены: предупреждения компилятора — это ошибки.
* Именование: `k_` — префикс ядра (`klog`, `k_port_write`), `board_` — плата,
  `drv_` — драйверы, `port_` — платформенный слой.
* Заголовочные файлы — с include guard'ами `MICRO_OS_..._H`.
* В ядре запрещены `printf`/`malloc` из libc напрямую: используйте `klog`,
  `kmm_alloc`, `k_port_write`.
* Никаких глобальных переменных без префикса `g_` и с суффиксом `_s`/`_ms`/`_kb`.

## Коммиты

Сообщения — в стиле Linux, с указанием области:

```
kernel: add task priority inheritance
vfs: fix path lookup for trailing slash
drivers: fix i2c timeout on mpu6886
docs: describe the stickc plus2 power model
```

Правила:

* одна логическая единица изменения на коммит;
* первая строка — до 72 символов, без точки в конце;
* в теле объясняйте *почему*, а не *что* — diff и так показывает что.

## Ветки и релизы

* `release_candidate` — ветка релиз-кандидата: каждый пуш в неё запускает
  проверки в облаке, как и в `mainline`. Тег вида `vX.Y.Z` собирает прошивку
  и публикует пакет как релиз GitHub; тег с дефисом (`vX.Y.Z-pre`) —
  пререлиз. Тесты контрибьютор гоняет локально, и их повторяет облако.
* `mainline` — всегда рабочее состояние, `make ci` зелёный.
* Фичи — в `feature/<что>`, баги — `fix/<что>`.
* Каждое крупное изменение архитектуры сопровождается ADR в `docs/adr/`.

## Тесты

* Юнит-тесты лежат в `tests/`, фреймворк — свой минимальный (`tests/framework/ktest.h`),
  внешних зависимостей нет.
* Тесты ядра обязаны работать на хосте: если для проверки нужен реальный ESP32 —
  это сигнал, что код смешивает платформенное и переносимое.
* Новый модуль ядра = новый файл в `tests/cases/`.
