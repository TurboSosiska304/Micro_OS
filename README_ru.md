# Micro OS

> English version: [README.md](README.md)

Linux-подобное ядро для **M5Stack StickC Plus2** (ESP32-PICO-V3-02, 240 МГц, 2 МБ PSRAM).

Цель — не «прошить ещё один ESP32-проект», а написать настоящее ядро: планировщик задач,
системные вызовы, VFS с `/proc` и `/dev`, менеджер памяти, драйверы и init-процесс,
который запускает шелл. Всё это — на голом железе без MMU, с одним ядром ESP32,
200 мА·ч батареей и экраном 135×240.

## Ключевая идея: переносимое ядро

Ядро **не знает про железо**. Вся платформенная часть вынесена в порт:

```
components/kernel/    ← чистый C11, ноль зависимостей от ESP-IDF
components/board/     ← описание платы
components/port_esp32/← реализация порта для ESP32 (ESP-IDF)
ports/port_host/      ← реализация порта для Linux (симулятор + тесты)
```

Следствие: ядро компилируется и тестируется на обычном компьютере за секунды.
Цикл «правка → тест → запуск» не требует прошивки устройства. А сборка самой
прошивки — обычный ESP-IDF проект.

## Сборка и запуск

### Хост (симулятор + тесты) — работает сразу

```bash
make test     # сборка и юнит-тесты
make sim      # запустить симулятор ядра на Linux
```

Или напрямую:

```bash
cmake -B build-host -S . -G Ninja
cmake --build build-host
ctest --test-dir build-host --output-on-failure
./build-host/ports/port_host/microos_sim
```

### Устройство (ESP-IDF)

Требуется установленный ESP-IDF v5.x:

```bash
git clone -b v5.3 --recursive https://github.com/espressif/esp-idf.git ~/esp/esp-idf
~/esp/esp-idf/install.sh esp32
. ~/esp/esp-idf/export.sh

idf.py set-target esp32
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

Либо через Makefile: `make idf-build`, `make idf-flash`, `make idf-monitor`.

Порт должен быть доступен текущему пользователю. В большинстве дистрибутивов
устройство принадлежит группе `uucp`:

```bash
sudo gpasswd -a $USER uucp   # затем перелогиниться
```

### Проверка ядра на устройстве

init-процесс запускает самотест на реальном железе: три задачи с разными
приоритетами спят, отдают управление и просыпаются, а init проверяет результат
и печатает `ps`-подобную таблицу списка задач.

```bash
tools/device-test.sh              # собрать, залить и проверить автоматически
tools/device-test.sh /dev/ttyACM0 # с явным указанием порта
tools/console.py                  # просто читать консоль
tools/console.py /dev/ttyACM0 20 --reset --send "modules"
```

Скрипт завершается с `RESULT: PASS`, если самотест прошёл.

### Доктор железа

После самотеста init-процесс обходит зарегистрированные модули и проверяет
их по очереди. Результат — отчёт:

```
module health report:
  module     state     detail
  psram      ok        2048 KB
  flash      ok        8 MB
  imu        ok        acc -16,-2952,16728 (raw)
  rtc        degraded  01:00:00 (no clock)
  display    ok        135x240, fb 63 KB
  input      ok        A=up B=up C=up
  buzzer     ok        passive, 2 kHz via LEDC
  led/ir     ok        G19, shared with the IR emitter
  battery    ok        4176 mV, 98% (raw 2088 mV)
  wifi       degraded  f4:65:0b:32:00:c0 idle
  mic        skip      SPM1423 MEMS microphone (I2S)
11 module(s), 0 problem(s)
```

`ok` — работает, `degraded` — работает с ограничениями (нет точки доступа, нет
часов без батарейки), `fail` — не работает, `skip` — пока не реализовано.
Команда `modules` повторяет проверку в любой момент.

### Шелл

init-процесс запускает шелл — небольшое подмножество команд Linux:

| Команда | Смысл |
|---|---|
| `help` | список команд |
| `ps` | список задач |
| `uptime` | время с момента загрузки |
| `uname` | имя и версия ядра |
| `free` | использование памяти |
| `dmesg` | журнал ядра |
| `modules` | повторная проверка модулей |
| `memtest` | проверка памяти и её скорости |
| `i2c` | сканирование шины I2C |
| `date` | время с RTC |
| `wifi` | станция WiFi: `status`, `scan`, `connect`, `join`, `disconnect` |
| `mfetch` | отчёт о системе с логотипом (аналог fastfetch) |
| `echo`, `sleep`, `clear`, `reboot` | как в жизни |

Команда `mfetch` — аналог fastfetch: слева логотип системы, справа короткий
отчёт о плате — версия и сборка, железо, память с блоками в ней, объём тома,
аптайм с задачами, модули и оболочка. Логотип — буква M символами шрифта 5x7
экрана: один рисунок служит и последовательному порту, и дисплею платы, а
сам отчёт — простой текст везде. `mfetch color` раскрашивает логотип.

```
microos> mfetch

MM MM  Build        Oct 26 2026 17:40:12
M M M  Board        M5Stack StickC Plus2
M   M  SoC          ESP32-PICO-V3-02
M   M  Arch         xtensa-esp32
       Display      1.14" TFT 135x240 (ST7789v2)
       Heap         112/272 KB free
       Psram        1917 KB free
       Allocs       0 block(s), 0 KB
       Volume       5828 of 5832 KB
       Uptime       12 s, 4 task(s)
       Modules      12, 0 problem(s)
       Shell        32 command(s)
```

### Станция WiFi

Радио платы — отдельный драйвер: переносимое ядро, которое держит состояние
станции, и радио ESP32, которое говорит с железом. Сеть прошлого раза
запоминается в NVS, поэтому после перезагрузки плата подключается к ней сама.

```
microos> wifi scan
3 network(s):
home            -42 dBm  ch  6  locked
guest           -70 dBm  ch 11  open
microos> wifi connect home secret
connecting to home
microos> wifi status
home aa:bb:cc:dd:ee:ff, ip 192.168.1.42, -42 dBm, ch 6
saved network: home
```

Решение о форме драйвера записано в
[docs/adr/0003-wifi-driver_ru.md](docs/adr/0003-wifi-driver_ru.md).

### Готовые бинарники

В папке `dist/` лежит собранная прошивка: приложение, загрузчик, таблица
разделов, скрипт прошивки и суммы файлов. Папки нет в репозитории — это
продукт сборки: `make bundle` собирает её после сборки прошивки, а готовые
образы уходят в релизы. Скачиваешь папку, подключаешь плату и запускаешь
`./flash.sh` — исходники, ESP-IDF и тулчейн не нужны.

## Проверки

Весь список проверок выполняется локально, перед пушем:

```bash
make ci          # сборка, тесты, санитайзеры, smoke-тест, целостность
```

Он собирает прошивку для ESP32 (ESP-IDF v5.3), гоняет юнит-тесты и
санитайзеры, smoke-тест устройства и проверку целостности репозитория:
заголовки образов, таблицу разделов против `partitions.csv`, объекты git и
форматирование исходников.

Автоматический CI/CD относится к ветке `mainline` и там будет своим; эта
ветка в облаке ничего не собирает. Тесты самого кода гоняет контрибьютор, а
после первого релиза они получат собственный CI/CD.

## Структура репозитория

```
Micro_OS/
├── components/
│   ├── kernel/         переносимое ядро: boot, log, panic, version
│   ├── board/          описание железа

│   └── port_esp32/     порт для ESP32
├── ports/port_host/    порт для Linux + симулятор
├── main/               точка входа прошивки (app_main)
├── tests/              юнит-тесты (свой минимальный фреймворк, без зависимостей)

└── Makefile            удобные цели: test, sim, ci, format, idf-*
```

## Стиль разработки

* C11, `-Wall -Wextra -Werror`, 4 пробела, стиль Linux/BSD-mix (см. `.clang-format`).
* Один коммит — одна логическая change; сообщения в стиле Linux:
  `subsys: add vfs mount table`, `drivers: fix ir carrier frequency`.
* Любое новое поведение ядра покрывается тестом в `tests/`.
* Форматирование: `make format`.
* Перед пушем: `make ci` (сборка, тесты, smoke-тест и проверка целостности).

Подробнее — [CONTRIBUTING_ru.md](CONTRIBUTING_ru.md).

## Ограничения, о которых стоит знать сразу

* **Нет MMU.** Разделение ядра и пользовательского кода логическое, а не аппаратное:
  нет аппаратной защиты памяти и полноценных адресных пространств.
* **`fork()` — заглушка.** MMU нет, поэтому адресное пространство родителя
  скопировать нельзя. `fork()` создаёт задачу, которая *делит память* родителя
  (как `CLONE_VM` в Linux) и *перезапускает программу родителя с начала* —
  работа, сделанная до вызова `fork()`, выполняется в ребёнке заново. Он
  отвечает номером ребёнка в родителе и 0 в ребёнке, так что программа
  сохраняет привычную форму POSIX, но ребёнок — не копия родителя в момент
  вызова. Настоящий `fork()` (своё адресное пространство, copy on write)
  запланирован сразу после первого релиза.
* **Один пользователь, без владельцев и прав отдельных файлов.** Защита
  файла — это доступ, с которым открыли его дескриптор (чтение, запись или то
  и другое), который ядро проверяет с кодом `EBADF`. Владельцы и `chmod` ждут
  первого релиза: сегодня на плате один пользователь.
* **8 МБ flash / 2 МБ PSRAM.** Приложение одно, обновления по воздуху нет:
  ядро занимает 2 МБ (`factory`), остальная флеш (5.75 МБ) отдана MicroFS.
  Вся раскладка — в [partitions.csv](partitions.csv).
* **ESP32-PICO-V3-02 без PMIC.** Питанием и сном управляет сам ESP32:
  вывод `HOLD` (G4) надо выставить в HIGH, иначе плата выключится.
* **Процент заряда — кривая, а не точный учёт.** Миллиампер-часы никто не
  считает: заряд ищется по напряжению ячейки — правда для покоящейся
  ячейки и приблизительность под нагрузкой. Пока вставлен USB, делитель
  видит напряжение заряда, и процент упирается в верх кривой (100%) — там
  честное число — напряжение из `modules`, а `battery` прямо пишет
  `(the charger is on)`.
* **Одна кнопка питания + две пользовательские** (A, B) и третья (C) у Plus2.
