# ABI системных вызовов

> Английская версия: [syscall-abi.md](syscall-abi.md)

Системные вызовы — это интерфейс между ядром и программами. Их номера —
**контракт**: они записаны здесь, они покрыты тестом, и они никогда не
меняются. Программа, собранная под одну версию ядра, работает и со
следующей.

## Соглашение

Как в Linux: номер вызова и шесть аргументов, результат — в возвращаемом
значении.

```c
k_ssize_t ksys_call(k_u32_t number, k_u64_t a0, k_u64_t a1, k_u64_t a2,
                     k_u64_t a3, k_u64_t a4, k_u64_t a5);
```

Аргументы **64 бита** на любой платформе. У ядра платы указатели 32-битные,
но тот же код проверяется на 64-битном хосте, а обрезанный пополам указатель —
это падение, которое проявится только на одной из двух платформ.

Отрицательный результат — ошибка, номера совпадают с кодами ошибок
`kernel/errno.h` (те же значения, что и в POSIX).

## The table

| Номер | Вызов | Аргументы | Результат |
|---|---|---|---|
| 0 | `exit` | `code` | не возвращается |
| 1 | `read` | `fd, buf, count` | число байт или ошибка |
| 2 | `write` | `fd, buf, count` | число байт или ошибка |
| 3 | `open` | `path, flags` | дескриптор или ошибка |
| 4 | `close` | `fd` | 0 или ошибка |
| 5 | `stat` | `path, buf` | 0 или ошибка |
| 6 | `lseek` | `fd, offset, whence` | новая позиция или ошибка |
| 7 | `unlink` | `path` | 0 или ошибка |
| 8 | `mkdir` | `path` | 0 или ошибка |
| 9 | `readdir` | `fd, buf, count` | число байт или ошибка |
| 10 | `getpid` | - | номер задачи |
| 11 | `getcwd` | `buf, size` | длина пути или ошибка |
| 12 | `ioctl` | `fd, cmd, arg` | 0 или ошибка |
| 13 | `yield` | - | 0 |
| 14 | `sleep` | `ms` | 0 |
| 15 | `uptime` | - | время с загрузки в миллисекундах |
| 16 | `reboot` | - | не возвращается |

Флаги `open` — те же, что и у VFS:

| Флаг | Значение |
|---|---|
| `KSYS_O_RDONLY` | только читать |
| `KSYS_O_WRONLY` | только писать |
| `KSYS_O_RDWR` | читать и писать |
| `KSYS_O_CREAT` | создать файл, если его нет |
| `KSYS_O_TRUNC` | обрезать файл до нуля |
| `KSYS_O_APPEND` | писать в конец |

`whence` у `lseek`: `KSYS_SEEK_SET` (от начала), `KSYS_SEEK_CUR` (от текущей
позиции), `KSYS_SEEK_END` (от конца).

## Дескрипторы

У каждой задачи своя таблица открытых файлов, четыре штуки. Дескриптор — это
номер ячейки. Не открытый дескриптор даёт `KERR_BADF`.

## Обёртки

Программы пользуются обёртками: они проверяют аргументы до того, как те
дойдут до ядра:

```c
int fd = ksys_open("/etc/config", KSYS_O_RDONLY);
char buffer[256];
int got = ksys_read(fd, buffer, sizeof(buffer));
ksys_close(fd);
```

Обёртки тонкие: они только передают аргументы дальше.

## Тесты

Тесты ABI не проверяют, что «что-то работает», они проверяют **свойства**:
одни и те же данные должны давать один и тот же результат, как бы программа
ни делила их на части.

* **Круговая проверка.** Корпус чисел записывается через системные вызовы
  кусками по 1, 3, 7, 64, 512, 1024 и 4096 байт. Каждый раз должны вернуться
  те же байты, и их сумма должна быть той же.
* **Выравнивание.** Те же данные, записанные из выровненного буфера и из
  буфера, сдвинутого на байт, дают одинаковый результат.
* **Номера вызовов.** Таблица выше повторена в тесте, чтобы изменение
  контракта было замечено сразу.
* **Ошибки.** Файла нет, дескриптор не открывался — одна и та же ошибка, как
  бы вызов ни делался.
* **Согласие.** Файл, который пишут системные вызовы, — это тот же файл,
  который видит файловая система.

Корпус лежит в [tests/corpus/vectors.txt](../tests/corpus/vectors.txt): 512
чисел, среди них граничные значения (0, 1, 255, 65535, 2147483647 и так
далее).
