# Roadmap Micro OS

> English version: [roadmap.md](roadmap.md)

Каждая фаза заканчивается рабочим состоянием на устройстве и зелёными тестами.

## Фаза 0 — Каркас (done)

* [x] Репозиторий, структура каталогов, лицензия, правила коммитов
* [x] Двухрежимная сборка: ESP-IDF (устройство) и хост (симулятор + тесты)
* [x] Переносимое ядро: типы, конфиг, лог с кольцевым буфером, паника, версия
* [x] Модель загрузки с уровнями подсистем и проверкой ошибок
* [x] Описание платы (SoC, flash, PSRAM, дисплей, IMU, RTC, питание)
* [x] Порт ESP32 (UART-вывод, таймер, критические секции) и порт для хоста
* [x] Юнит-тесты (свой фреймворк, без внешних зависимостей)
* [x] Документация: README, CONTRIBUTING, архитектура, железо, ADR

**Не входит (осознанно):** инициализация дисплея и кнопок требует ESP-IDF.

* [x] `struct task`, состояния, приоритеты, выделение PID
* [x] Переключение контекста (поверх FreeRTOS), `k_sched_yield`, `k_sched_sleep_ms`
* [x] Очереди готовых задач по приоритетам, очередь спящих, тик 1 мс
* [x] `init` как PID 1, запуск «пользовательских» задач
* [x] Тесты: жизненный цикл задачи, приоритеты, очередь, сон, тики
* [x] Квант времени (как `SCHED_RR`), настраиваемая величина
* [x] Родитель/потомок, `task_wait()`, `task_wait_any()`
* [x] Таблица файловых дескрипторов и рабочий каталог у задачи
* [x] `/proc/<pid>` (относится к фазе 2)
* [ ] Настоящий `fork()` — копия адресного пространства (нужен собственный

      память родителя и перезапускает его программу с начала (см. «Известные
      ограничения» в README), это будет исправлено сразу после первого релиза

Результат печатается отчётом: `ok`, `degraded`, `fail` или `skip`.

* [x] Реестр модулей в ядре (`kernel/kmod`) с инициализацией и проверкой
* [x] Экран (ST7789v2, кадровый буфер в PSRAM, тестовая картинка)
* [x] Кнопки A, B и C
* [x] Буззер (LEDC, 2 кГц)
* [x] Красный LED и ИК-диод (общий пин G19)
* [x] IMU (MPU6886 по I2C)
* [x] RTC (BM8563 по I2C)
* [x] Напряжение батареи (ADC на G38)
* [x] WiFi-радио
* [x] PSRAM и flash
* [x] Команда `doctor`, повторяющая проверку в любой момент (как команда "modules")

## Фаза 2 — VFS, MicroFS, шелл

* [x] Шелл: переносимый интерпретатор команд с реестром команд
* [x] Встроенные команды: `help`, `uname`, `uptime`, `ps`, `echo`, `sleep`,
      `dmesg`, `free`, `clear`, `reboot`, `modules`, `memtest`, `i2c`
* [x] `memtest`: размер внутренней кучи и PSRAM, скорость обоих (заполнение,
      контрольная сумма, копирование) с проверкой целостности данных
* [x] `mfetch`: отчёт о системе с логотипом из `logos.md` (аналог fastfetch,
      логотип слева, отчёт справа)
* [x] Консоль в порту ESP32 (драйвер UART делает ввод рабочим)
* [x] MicroFS: файловая система платы по дизайну из
      [docs/memory_ru.md](memory_ru.md): секции DATA, META и INFO, адреса
      секций вычисляются из размера тома
* [x] VFS: дерево каталогов, файловые системы монтируются в его точки
* [x] Команды работы с файлами: `ls`, `cat`, `write`, `mkdir`, `rm`, `cd`,
      `pwd`, `df`, `mount`
* [x] Том во флеше: раздел 5.75 МБ, данные пользователя переживают перезагрузку
* [x] `/proc`: `version`, `uptime`, `meminfo`, `tasks`, `modules`
* [x] `/dev`: `tty0` (консоль) и `null`
* [x] Консоль на дисплее: вывод шелла зеркалится на экран платы, шрифт 5x7
* [x] Короткая справка: одна строка на команду, `help <команда>` расскажет
      подробнее
* [x] Лог загрузки уходит в `/log/start.log`, консоль остаётся читаемой
* [x] Терминал повторяет введённое, диалог виден и в интерактивном консоле
* [x] Картинка на дисплее: у ST7789V2 память 240x320, стекло панели 1.14"
      показывает только часть её. Смещение меняется на лету: `display <x> <y>`
* [x] Терминал повторяет каждый символ во время ввода, backspace стирает его
* [x] `/proc/self` и каталог на каждую задачу с файлом `status`
* [ ] История команд, автодополнение по tab (пока не нужны)

## Фаза 3 — Память и ABI системных вызовов (done)

* [x] ABI системных вызовов: номера — это контракт, они записаны в
      [docs/syscall-abi_ru.md](syscall-abi_ru.md) и покрыты тестом
* [x] Вызовы для работы с файлами: open, read, write, close, stat, lseek,
      unlink, mkdir, readdir, getpid, getcwd, ioctl, yield, sleep, uptime
* [x] Тесты работают с корпусом настоящих чисел: одни и те же данные
      должны давать одинаковый результат, как бы их ни делили на части
* [x] Процессная часть ABI: fork, getppid, waitpid. Память родителя
      не копируется, задачи делят её, как CLONE_VM. Библиотека даёт
      fork() форму POSIX - 0 в ребёнке, номер ребёнка в родителе, - но
      ребёнок перезапускает программу родителя с начала (настоящий
      fork ждёт первого релиза)
* [x] libc поверх ABI: printf, open, read, write. Библиотека проверяется
      библиотекой системы на настоящих числах корпуса
* [x] `kmm_alloc`/`kmm_free`, выделение из PSRAM, слабы для маленьких блоков
* [x] Память программ: malloc, free, realloc и calloc поверх ABI
* [x] Таблица системных вызовов, единый ABI
* [x] Минимальный libc поверх ABI: `open/read/write/close/printf`. Память
      (`malloc`) пока отсутствует
* [x] Модель прав и «файловых дескрипторов»: дескриптор помнит, с каким
      доступом его открыли, и ядро отказывает читать дескриптор, открытый
      только на запись, или писать в дескриптор, открытный только на чтение, —
      с кодом `EBADF`. Правило живёт на границе системы, поэтому любая
      файловая система отвечает одинаково. Владельцы и права отдельных файлов
      ждут первого релиза — сейчас пользователь один (см. «После первого
      релиза»)

## Фаза 4 — Драйверы

* [x] `drv_framebuffer`: ST7789v2, 135×240, поворот, вывод текста и графики
      — кадровый буфер живёт в `drv_display`: картинка поворачивается в
      программе (панель остаётся в портрете, поэтому смещение видимой
      области не меняется), графика — `pixel`, `fill_rect`, `rect`, `line`,
      а в шелле `display rotate <0|90|180|270>` и `display draw [секунды]`
      — тестовая картинка для глаз
* [x] `drv_input`: кнопки A/B/C, debounce, события ввода — команда
      `input [seconds]` и файл `/dev/input`
* [x] `drv_buzzer`: пассивный зуммер на G2, для пользователя команда `beep`
* [x] `drv_led`: красный LED на G19 (общий с ИК-излучателем), команда `led`
* [x] Два «прикола» для человека на LED: `led heart` — свет «дышит»,
      `led dance` — светодиод танцует
* [x] `drv_battery`: оставшийся заряд в процентах, по кривой одной ячейки —
      команда `battery`
* [x] `drv_imu` (MPU6886): акселерометр, сырые значения в отчёте доктора
* [x] `drv_rtc` (BM8563): дата и время часов — команда `date` и
      `date set <YYYY-MM-DD> <HH:MM:SS>`, и вердикт доктора по флагу LV
      и диапазонам полей (мёртвая батарейка видна сразу)
* [ ] Будильник RTC: пробуждение платы из deep sleep
* [x] `drv_wifi`: станция, сканирование, сеть прошлого раза запоминается
      в NVS (см. [ADR 0003](adr/0003-wifi-driver_ru.md))
* [x] Консоль на TFT + UART одновременно
