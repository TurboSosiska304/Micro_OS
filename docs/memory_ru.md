# Файловая система MicroFS (MFS)

> English version: [memory.md](memory.md)

## 1. Общая схема

MicroOS использует собственную файловую систему — **MicroFS** (MFS). Весь доступный объём накопителя делится на три раздела. Каждый раздел состоит из целого числа блоков по 1024 байта.

```
              MFS VOLUME
┌──────────────────────────────────────┐
│  DATA                                │
│  Данные файлов и каталогов           │
│  Размер зависит от накопителя        │
├──────────────────────────────────────┤
│  META                                │
│  Индекс + таблица записей            │
│  Размер зависит от числа объектов    │
├──────────────────────────────────────┤
│  INFO                                │
│  Заголовок MFS                       │
│  Фиксированное число блоков          │
└──────────────────────────────────────┘
```

| Раздел | Назначение |
|---|---|
| `DATA` | хранение данных файлов и каталогов |
| `META` | таблицы индексации, прав доступа и т. д. |
| `INFO` | самый важный раздел: данные о самой ФС (размер блока, смещения разделов и т. д.) и о корневом каталоге |

## 2. Относительная адресация

MFS использует относительную адресацию: адреса разделов не хранятся жёстко, а рассчитываются из ёмкости накопителя. Для этого каждый раздел описывается тремя параметрами:

| Поле | Значение |
|---|---|
| `start` | номер начального блока |
| `blocks` | количество блоков |
| `size` | размер в байтах |

Расположение разделов в томе:

```
block 0                                         block N-1
   │                                                │
   ▼                                                ▼
   ┌───────────────────────┬───────────────┬────────┐
   │         DATA          │     META      │  INFO  │
   └───────────────────────┴───────────────┴────────┘
   0                  META_start      INFO_start    N
```

Исходные параметры:

| Обозначение | Значение |
|---|---|
| `N` | общее количество блоков в томе |
| `I` | количество блоков раздела `INFO` |
| `M` | количество блоков раздела `META` |

Формулы смещений и размеров:

| Величина | Формула |
|---|---|
| `INFO_start` | `N - I` |
| `META_start` | `N - I - M` |
| `DATA_start` | `0` |
| `DATA_blocks` | `N - I - M` |

> **Преимущество:** для тома любой ёмкости не нужно отдельно хранить или жёстко прописывать адреса областей — вся структура рассчитывается «на лету», например при подключении нового накопителя или изменении размера существующего.

## 3. Пример на разных размерах

Пока используются такие правила:

* блок — 1024 байта;
* `INFO` — 1 блок;
* `META` — 4% от общего числа блоков, округлённые вверх;
* `DATA` занимает всё оставшееся место.

| Размер тома | Всего блоков | DATA | META | INFO |
|---|---|---|---|---|
| 64 КиБ | 64 | 60 | 3 | 1 |
| 256 КиБ | 256 | 244 | 11 | 1 |
| 1 МиБ | 1024 | 982 | 41 | 1 |
| 6 МиБ | 6144 | 5897 | 246 | 1 |
| 16 МиБ | 16384 | 15727 | 656 | 1 |

`DATA` и `META` масштабируются автоматически, но у процентного распределения есть нюанс: на малом накопителе 4% под `META` может не хватить для большого числа мелких файлов, а на большом — это окажется больше, чем нужно.

## 4. Распределение META по числу записей

Более удачный подход — считать размер `META` не в процентах от тома, а по ожидаемому числу объектов:

```math
META_table = ceil(E * 16 / 1024)
```

где `E` — максимальное число записей (файлов и каталогов), а 16 — размер одной записи таблицы в байтах. Подход пока не реализован (см. раздел 6).

## 5. Хранение данных в INFO

Вместо жёстко заданных адресов `INFO` хранит универсальное описание областей. Дополнительно в заголовке лежат `magic`, `version`, `block_size`, `total_blocks`, `root_inode` и `features`.

```
INFO
┌────────────────────────────────┐
│ magic                          │
│ version                        │
│ block_size                     │
│ total_blocks                   │
├────────────────────────────────┤
│ data_start                     │
│ data_blocks                    │
├────────────────────────────────┤
│ meta_start                     │
│ meta_blocks                    │
├────────────────────────────────┤
│ info_start                     │
│ info_blocks                    │
├────────────────────────────────┤
│ root_inode                     │
│ features                       │
└────────────────────────────────┘
```

## 6. Возможные улучшения

Автоматическое распределение областей тома:

- [ ] Реализовать автоматическое определение размера `META` при форматировании.
- [ ] Рассчитывать вместимость `FILE TABLE` на основе доступного пространства.
- [ ] Учитывать служебные структуры и bitmap свободных блоков при расчёте.
- [ ] Сохранять фактические границы `DATA`, `META` и `INFO` в заголовке файловой системы.
- [ ] Проверять корректность разметки при монтировании тома.
