# Фаза 1F — доктор железа

Процесс загрузки обходит зарегистрированные модули и проверяет их по
очереди. Результат — отчёт: `ok`, `degraded`, `fail` или `skip`.

```
module health report:
  module     state     detail
  psram      ok        2048 KB
  flash      ok        8 MB
  imu        ok        acc 1644,-228,16784 (raw)
  rtc        degraded  25:00:00 (no clock)
  display    ok        135x240, fb 63 KB
  input      ok        A=up B=up C=up
  buzzer     ok        passive, 2 kHz via LEDC
  led/ir     ok        G19, shared with the IR emitter
  battery    ok        4170 mV (raw 2085 mV)
  wifi       degraded  f4:65:0b:32:00:c0 idle
  mic        skip      SPM1423 MEMS microphone (I2S)
11 module(s), 0 problem(s)
```

`degraded` значит, что модуль работает, но с ограничением: радио без точки
доступа, часы RTC без батарейки.

## Ошибки, которые стоили времени

Каждую из них нашёл доктор, а не тесты на хосте.

* **Флеш ESP32 умеет только сбрасывать биты.** Сектор, который пишется поверх
  старых данных, требует, чтобы биты шли из 0 в 1, и драйвер отказывает.
  Адаптер файловой системы читает сектор, меняет нужную часть, стирает
  сектор и пишет его обратно. Сектор, который меняется, держится в памяти,
  чтобы ради мегабайта не стирать килобайт.
* **Изменения формата не доходили до флеша.** Том монтировался из памяти
  кэша сектора и после перезагрузки оказывался сломанным. Форматирование
  обязано вызывать sync устройства в конце.
* **SPI дисплея вызывался с хостом вместо дескриптора.** Драйвер
  разыменовывал маленькое число, и плата падала с исключением LoadProhibited.
* **40 МГц — слишком быстро для SPI через GPIO-матрицу.** Предел 26,7 МГц,
  дисплей работает на 20 МГц.
* **DMA SPI не читает PSRAM.** Кадровый буфер отправляется на панель
  кусками по 4 КБ через буфер во внутренней памяти.
* **Последний аргумент `i2c_master_transmit()` — это таймаут в
  миллисекундах, а не флаг.** Значение `true` означало 1 мс, и обмены
  обрывались в зависимости от фазы загрузки.
* **`esp_timer_create()` ждёт аргументы в обратном порядке.** Обработчик
  читался не из того места, и база времени не запускалась.
* **Стек задачи был слишком мал.** Буфер каталога — 4 КБ, и он лежал на
  стеке. Стек задачи теперь 8 КБ, а большие буферы статические.
* **Паника должна доходить до консоли даже тогда, когда лог собирается.**
  Падение платы выглядело как просто молчащая плата.

## Что стоит запомнить

* Доктор — не формальность, а инструмент, который находит ошибки железа.
  Каждая из ошибок выше выглядела как «устройство сломано», а виноват был
  код.
* Отчёт доктора — тот же, что в `/proc/modules`.
* `degraded` — это не `fail`: модуль работает, и сломанным считать его не
  надо, иначе система начнёт «чинить» то, что не сломано.
