# Debts of Micro OS

This is the single register of what the tree knows it does not do. A debt is a
gap between what a document promises and what the code does, or a limitation
with a next step that somebody can take. A decision is not a debt: the choices
that are final are listed in their own section, so that a reader does not try
to "fix" them.

The sources of the register are [roadmap.md](roadmap.md) (K3-K7),
[phase7.md](phases/phase7.md) ("What is still missing"),
[ports/esp32/README.md](ports/esp32/README.md) and
[ports/esp32/roadmap.md](ports/esp32/roadmap.md) (P3-P5), the other port
READMEs, [ports/x86_64/iso.md](ports/x86_64/iso.md) and
[ADR 0026](adr/0026-bios-iso.md), [ADR 0005](adr/0005-programs-and-protection.md),
[README.md](../README.md) ("Known limitations"), [libc.md](libc.md),
[memory.md](memory.md) and [syscall-abi.md](syscall-abi.md).

| Status | Meaning |
|---|---|
| `open` | Known, not started; the next step is written in the last column. |
| `in work` | Somebody is changing the tree for it now. |
| `decision` | Deliberate, not a debt; the reason is in "Decisions, not debts". |

A debt is closed by code and a test, not by deleting its row: when it is done
the row moves to the release notes of the phase that did it.

## K3 - Programs

| Debt | Where | Status | What it needs |
|---|---|---|---|
| `stat` reports the mode and the owner to anybody and checks nothing. | `components/kernel/src/ksys.c`, `docs/phases/phase7.md` | decision | None: POSIX makes `stat` readable, and the check stays at `open` and `execve`. |

The release notes of 1.2.1 carry the row. |
| The header of an image names the machine (`arch` 1 is Xtensa, ADR 0018) and the ESP32 port runs one, but the windows are fixed addresses and one program at a time: a program of the board that calls `execve` would overwrite the text it is running from, and the port answers `ENOMEM` for the second. | `components/port_esp32/src/port_exec.c`, ADR 0018 §3 | open | A pool of windows (two, or a window per task) or a loader that copies the program out of the window of the caller. |
| A program of the board shares the address space of the kernel: a bad pointer that reaches a call of the kernel (or a fault in the program's own text) is a `Guru Meditation`/panic and a reboot, not the end of one task. Measured with `stat((char *)0xFFFFFFF0, ...)` from `/bin/hello`: `LoadProhibited`, `EXCVADDR 0xFFFFFFF0`, a backtrace with the frames at `0x4009Exxx`, then `Rebooting...`. | `components/port_esp32/src/port_exec.c`, ADR 0018 §4 | open | An exception handler of the port that knows the windows of the program and ends its task where the fault is in them; an MMU (not this board) for the rest. |
| A program of the board is a file of the `progs` partition, mounted read-only at `/bin`; the directory and the 64 KiB slots are in ADR 0022, the image is built by `tools/progs_image.py`, and no image of a program is embedded in the firmware. | The programs of `progs` are read with `esp_partition_read()` and copied into the IRAM/DRAM windows; the flash is not mapped as instructions, so a program costs a copy in RAM for the time of the load. | `components/port_esp32/src/progs_vfs.c`, `port_exec.c`, ADR 0022 §4 | decision | None for 1.1: the copy is the path 1.0 measured and the mapping needs a fixed virtual address reserved by the first `esp_partition_mmap()` of the boot and a program linked for it. |
| The windows of a program of the board are 8 KiB of text and 8 KiB of data; a larger image is `ENOMEM`, and the compiler flags the text arena when the kernel grows into it. The stack of the program is the 8 KiB stack of a kernel task, shared with the kernel calls it makes. | `components/port_esp32/src/port_exec.c`, `exec_windows.ld`, `programs/program_esp32.ld` | decision | None for 1.0: `hello` and `cat` use about 2 KiB of text and 300 bytes of data. A bigger arena costs IRAM the kernel does not have. |
| The programs of `/bin` are written into a MicroFS volume of the raw image by the host tool, and the boot mounts that volume. A FAT volume of the same machine is mounted and writable, but no tool puts a program on it and the boot does not look for `/bin` there. | `tools/mkfs_mfs.c`, `ports/port_x86_64/src/kmain.c`, ADR 0008 | open | An installer that writes a program to the filesystem of the person's choice, and a `PATH` (or a mount of the image) that reaches it. |
| The environment of a program is the four words of the kernel (`k_exec_environ`): the shell has no `export`, so a program cannot be given `PATH`, `HOME` or a variable of the line. | `components/kernel/src/exec.c`, `components/kshell` | open | An environment of the shell, `set`/`export`, and the vector of the shell passed to `execve` instead of NULL. |
| The arguments and the environment of a call are bounded by eight words and 512 bytes each, a number of the frame of `execve`, not of the machine. | `components/kernel/src/ksys.c` (`KSYS_ARGV_MAX`, `KSYS_ARGV_BYTES`), `ports/port_x86_64/src/port_exec.c`, `components/port_esp32/src/port_exec.c` | open | A larger frame, or a vector copied into a block of `kmm` and freed after the program ends. |
| A program inherits the table of its caller now: `k_port_exec_enter()` makes the program with `task_fork_shared()`, so `cat < file`, a pipe end at 0 and `ls /bin | wc -l` reach it (ADR 0017). The descriptor 0 of a program at the prompt is the terminal of the task as a **fallback**: `read(0)` and `ioctl(0)` answer the console while nothing is open on 0 (ADR 0051 §2), so `cat` with no name reads the keyboard, and `fstat(0)` still says `EBADF` because no descriptor is open. | `components/kernel/src/ksys.c`, `ports/port_x86_64/src/port_exec.c` | partial | The port opening `/dev/tty0` on 0, 1 and 2 before it enters a program, which is then a descriptor of the task and not a fallback: `fstat`, `poll` and `dup2` of it answer like any other, and a program has thirteen free slots instead of sixteen. |
| The console of a program at the prompt is a **fallback and not a descriptor**: 1 and 2 are written to the console while they are not open as a file, so `open`/`pipe` of the kernel hand them out first, and a program of POSIX that opens a file and then writes its answer to 1 wrote the answer into its own file (`/bin/ports/tee` of `make ports-smoke` was the case). The library compensates (`src/syscall.c`: a new descriptor that lands on 1 or 2 moves to the lowest free number above them), which leaves a program at the prompt two open files - 0 and 3 - and a third one is `EMFILE`. | `components/libc/user/src/{syscall,unistd_ext}.c`, `components/kernel/src/ksys.c` (`sys_write`), `ports/port_x86_64/src/port_exec.c` | partial | The row above: 0, 1 and 2 as descriptors of the task, and then `open` never takes them and the move of `src/syscall.c` is not needed. |
| The library of a program is a second library, not a mode of the first: `components/libc` (of the kernel) and `components/libc/user` share the header of the ABI and nothing else. The second now has a heap of its own (an arena in the bss that grows with `brk` since 1.8), `errno`, the streams (the port of zlib needed them) and the formatter of a real number with `strtod` and a small `math` (SQLite needed them). | `components/libc/user` | decision | None for the size of the machine: a program of the board is a command of the kernel, and the programs of x86-64 are the ones a static image can carry. On a machine without an MMU the heap is the arena, because `brk` answers `ENOSYS`. |
| The ABI had no `chdir`: the shell moved the cwd of its task (a field of the kernel) and `execve` carried it into a program, but a program could not move its own; the library kept a directory of its own (`components/libc/user/src/path.c`), and a child started by `execve` began in the directory of the task and not in the one the program moved to. | `components/kernel/include/kernel/ksys.h`, `components/libc/user/src/path.c` | done | Closed in 1.8: the call 48 `chdir` moves the field of the task, the library resolves against `getcwd` and keeps no copy, and `tests/cases/test_ksys_process.c` (`ksys: chdir moves the task...`) and `/bin/chdir` in `make x86-smoke` are the gate - the child of a fork begins in the new directory. |
| The machine had no wall clock: the kernel counted milliseconds since the boot, the RTC existed only on the board and nothing seeded the kernel with it, and the library's `time()` answered the seconds of the boot while `localtime` was UTC. | `components/libc/user/src/time.c`, `components/drivers/src/drv_rtc.c`, the x86-64 port | done | Closed in 1.8: the call 49 `clock_gettime` (`CLOCK_REALTIME` and `CLOCK_MONOTONIC`), the boot seeds the kernel from the source of the machine (the process of the host, the CMOS of x86-64, the BM8563 of the board) and `ntp`/`date set` write it back; `time()`, `gettimeofday` and `clock()` read it. The zone of `/etc` is the K10 work. |
| `fstat` has no call of its own: a descriptor knows its position and not its name, so the library asks `lseek` for the size and calls a descriptor that cannot seek a pipe. A file that changes between the two calls is read at the wrong size by `tail -f`. | `components/libc/user/src/stat.c` | open | A `KSYS_FSTAT` on the file of the descriptor, with the same `struct vfs_statx` as `stat`. |
| A terminal is not one: the `ioctl` of the ABI answers `EINVAL` for every request, `isatty` is 0, and `<termios.h>` answers `ENOTTY`. A command that colours its output or reads a key without a line waits for a terminal driver. | `components/kernel/src/tty.c`, `components/kernel/src/ksys.c` (`sys_ioctl`), `components/libc/user/src/termios.c` | done | Closed in 1.9: `/dev/tty0` and `/dev/tty` are the terminal of the task (ADR 0051), `ioctl` answers `TCGETS`/`TCSETS`/`TIOCGWINSZ`/`FIONREAD`, the library has `tcgetattr`, `tcsetattr`, `cfmakeraw`, `ioctl` and an `isatty` that asks, and the gate is `tests/cases/test_tty.c`, `/bin/ports/ttyprobe` and `/bin/ports/kilo` (a full-screen editor of somebody else, built with no patch). |
| A resize of the terminal is not a signal: `SIGWINCH` is a number of the library and `signal()` answers `SIG_ERR` for it, so an editor that would redraw itself at a new size is told about nothing (ADR 0051, the last section). | `components/libc/user/include/signal.h`, `components/kernel/include/kernel/signal.h` | open | A signal of the ABI for the resize (a number of `K_SIG*` and a row of `docs/syscall-abi.md`) and a port that raises it where the screen changes size. |
| The arrows, Home, End, Page Up and Page Down of the console of x86-64 are not in the character stream: the decoder gives the extended keys to the interface (`/dev/input0`, ADR 0028) and the console pushes only the characters a shell types, so an editor moves with the letters, the Enter and the Backspace. | `ports/port_x86_64/src/ps2.c` (`key_handle`, `k_input_set1_key`) | open | The decoder pushing `ESC [ A` and its siblings into the ring of the console when no program holds `/dev/input0`, and a row of the test of the keyboard (`make x86-vga-smoke`). |
| The terminal of a session of telnet has no negotiated size and cannot be asked whether a byte waits: `struct k_terminal` has `get` and no `ready`, so `TIOCGWINSZ` answers 80x25 and `VMIN`/`VTIME` of a session over the wire is the blocking read of the socket. | `components/kernel/include/kernel/console.h`, `components/kernel/src/tty.c`, `components/telnet` | open | The NAWS option of the protocol, a field of the size in `struct k_terminal` and a `ready` that a socket answers without a read. |
| A cell of the screen has one of the sixteen colours of the console: `ESC[38;5;...m` and `ESC[48;5;...m` are not read, and a program that asks for a colour of 256 is drawn in the nearest of the sixteen (or in the pair of the theme). | `components/kernel/src/ansi.c`, `ports/port_x86_64/src/fb.c` | decision | None for a program of a character screen: the frame is RGB565 and a cell carries an attribute of a nibble. A terminal of 256 colours is a second representation of a cell. |
| The console has no scroll region and no insert/delete of a line: `ESC[r`, `ESC[L` and `ESC[M` are dropped, and a full-screen program repaints the cells it wants instead (`kilo` does exactly that). | `ports/port_x86_64/src/console.c` | open | The region in the state of the console and the three sequences; a screen that scrolls a part of itself is the same loop `scroll` does now, told which rows. |
| The guest has no floating point by default: `-mgeneral-regs-only` keeps the XMM state out of a program, and the library has no `strtod`/`%f` for the programs of the tree. A port that needs a real number (SQLite's `REAL`, Lua) is built **without** the flag, with `src/format_float.c`, `src/strtod.c` and `src/math.c`; the port turns CR4.OSFXSR and CR0.NE on, and the scheduler saves and loads the state at every switch, so several such programs may compute at once (K9 is closed below). | `ports/port_x86_64/CMakeLists.txt`, `components/libc/user/src/format_float.c`, `third_party/sqlite/README.md` | done | None. |
| A program has sixteen descriptors and the kernel gives the lowest free one: a program that opens two files can be given 1 or 2 and shadow the console, which is a console only while it is not open (`sys_write`). The library of a program does not move a descriptor; the recursive `grep` of sbase closes a directory before it visits a child to stay under the two. | `components/kernel/src/kfile.c`, `components/kernel/src/ksys.c` (`sys_write`), `third_party/sbase/grep.c` | open | Reserve 0, 1 and 2 for a program at the entry (open the console on them), or a call that opens at or above a number. |

Closed in the same pass: the `int $0x80` entry and its ABI, `argv` through

## K4 - Protection

| Debt | Where | Status | What it needs |
|---|---|---|---|
| `fork()` on a machine without an MMU is still a placeholder: the child shares the memory of the parent and re-enters its program. On x86-64 the call is real - an address space per task, copy on write and `k_port_fork_copy()` (contract 1.5) - and the board keeps the placeholder because it has no MMU. | `components/kernel/src/ksys.c`, ADR 0005, ADR 0007 | done | An MMU on the board, or the same placeholder for as long as it has none. |
| `KERNEL_NOMMU` is still 1 everywhere: the x86-64 port protects a program of ring 3, but the generic kernel does not use the MMU for a task and the board has none. | `components/kernel/include/kernel/config.h`, `ports/port_x86_64` | open | Page tables per task and the flag turned off for the ports that have an MMU. |
| The group triad of a mode is never the one the check reads: `vfs.c` compares `info.owner` with the uid of the caller and takes the nine bits of the owner or of the others, `struct vfs_stat` has no group, and no filesystem but MicroFS keeps one. The record of a version 3 volume **has** it (ADR 0038: `mfs_inode_group()`, `mfs_chgrp()`, `struct statx::group` in the hole after `type`), so the storage and the answer of `statx` are done and the meaning is not. ADR 0044 records the shape of the rest: a `chgrp` at number 48 of the ABI, a `chgrp` operation of `vfs_operations` with an adapter in each filesystem, `struct vfs_stat::group` and the triad of the group in `caller_bits()`, `/etc/group` with `getgrgid`/`getgrnam`, and the group of a new object from the gid of its maker. | ADR 0005, ADR 0033, ADR 0038, ADR 0044, `components/kernel/src/vfs.c`, `components/kernel/src/ksys.c`, `components/mfs/src/mfs_vfs.c`, `components/fs_ext2`, `components/libc/user/src/pwd.c` | partial | The five steps of ADR 0044 "The decision: the group waits", with the test matrix of that section. |
| The accounts of `/etc` are a file and the session is the door (ADR 0033, ADR 0044): `login`, `su`, `id`, `logout`, `who` and `whoami` are commands of the shell of the kernel, a task has one credential and no saved uid, and there is no setuid bit in `MOX1`. The hash of a password is a salted SHA-256 and not a key-derivation function, and there is no `passwd` to change one: a person edits `/etc/shadow` with `printf 'salt%s' password \| sha256sum`. Since 1.8 a session is a task with a terminal, the init of every port is its getty, `telnet` asks for the password of the socket (the defect of 1.6 is closed and `make x86-net-smoke` proves it), and the file a user makes is the user's. | `components/config/src/config_users.c`, `components/config/src/config_login.c`, `components/config/src/config_session.c`, `components/telnet/src/telnet_server.c`, `components/libc/user/src/pwd.c`, ADR 0033, ADR 0044, `docs/syscall-abi.md` | partial | A `passwd` command with a source of entropy in the kernel port (`k_port_random`, which does not exist), a `$argon2id$` (or `$bcrypt$`) line of `/etc/shadow` beside the `$sha256$` one, and, when a program needs it, the setuid bit of `MOX1` with a saved uid in `struct task` (the shape is the last section of ADR 0044). |
| A program started from a session of telnet does not inherit the terminal of the session: its descriptors 0, 1 and 2 are not opened to the terminal of the task, so `cat` of a program reads the UART and its output goes to the console of the machine. The commands of the shell - `login`, `su`, a line of the shell - are the ones the session owns; a program is not. | `ports/port_x86_64/src/port_exec.c`, `components/kernel/src/ksys.c`, `components/config/src/config_session.c` | open | The entry of a program opens its descriptors 0, 1 and 2 on the terminal of the task (the row of the descriptors of a program below), or a call of the ABI that opens the terminal of a session as a file; the two are the same work as the socket call of `/bin/httpd`. |
| The file a task of another uid creates was owned by uid 0 until 1.8: `vfs_open`/`vfs_mkdir` carried no owner into the create path, so a file made by uid 7 had owner 0 until root `chown`ed it. Since 1.8 the VFS gives the object it made to the uid of its maker (the `chown` operation of the filesystem, in the same call), and `make x86-smoke` asserts `owner: 7`. The gid of the object is still the gid of the design: no filesystem operation sets a group (the row of the group above). | `components/kernel/src/vfs.c`, `components/mfs/src/mfs.c`, `components/fs_ext2`, `components/fs_fat32`, `tools/x86_smoke.py` | done | The gid of the maker on a new object comes with the group of ADR 0044; the uid does not change. |
| `chmod 000` cannot be expressed: a zero mode means "the record predates the modes" and is refused instead of stored. | `docs/memory.md` section 6, `components/mfs/src/mfs.c` | decision | None without a format change; a real zero needs a bit that says "the mode is set". |
| The memory limit counts the user blocks a task allocated and has not freed, but the kernel keeps no list of the blocks of a task: a block that outlives the task that allocated it is not charged to anybody, and a task that exits with blocks still held leaves them to the system. | `components/kernel/src/kmm.c`, `components/kernel/src/task.c` | open | A list of the blocks in `struct task`, walked at the exit and by a check of the limit, or a header that names the owner strongly enough to free at the end. |
| The CPU limit is accounted at the edge of a system call and at the tick of a port that can name the running task: a task of the host or of the board that never makes a call is only marked at its next call. A program of ring 3 on x86-64 is marked by the tick. The host has no preemption of its own, so the time between two calls is wall time and includes the time the process gave to another task. | `components/kernel/src/{task,sched,ksys}.c`, `ports/port_host` | open | A tick that can name the running task on every port (the thread pointer of the board), or a preemption point that charges the time. |
| A limit only goes down: `setlimit` answers `EPERM` to a raise, even to the value it had a moment ago. A shell that lowered `ulimit -n 2` cannot come back to four without a reboot. | `components/kernel/src/task.c`, `docs/syscall-abi.md` | decision | None: the ceiling belongs to the machine, and root does not lift it either. A second limit (a hard one, as in POSIX) would be the way to grant a raise. |
| The child of a `fork` of a program comes back with the registers the iret path restores, and its stack was a view of the parent's instead of a copy. Two bugs, both fixed: the clone wrote the copy-on-write bit into both tables but flushed the TLB with an address 32 MiB above the page (the base of the window was counted twice), so the parent's next write after the fork went to the frame the child was about to return into; and the child's RAX was already zero in the copied frame but the library worked around it. `port_x86_64_paging_space_clone()` now flushes the address it changed, the frame carries the zero of POSIX, and the library's `fork()` is the plain call - no `getpid()` test, no yield. | `ports/port_x86_64/src/paging.c`, `port_exec.c`, `components/libc/user/src/unistd_ext.c` | done | Nothing: `/bin/procs` (a child that computes, a double fork and the status of each) is in `make x86-smoke`. |
| `execve` of a program is the POSIX shape on x86-64: the caller was a program of ring 3, the image replaces its memory and the frame of the call is rewritten into the entry of the new program - the call does not return to the old code, and the task keeps its pid, parent, descriptors and directory. A caller with no address space (the shell) still starts the program as a task of its own and waits for it, which is the honest shape for a kernel task. | `components/kernel/src/ksys.c` (`sys_execve`), `ports/port_x86_64/src/port_exec.c` | done | Nothing on x86-64. The board's placeholder of a machine without an MMU keeps the old shape. |
| The stack of the shell is 16 KiB and a deep command fills it: adding one `int` to the frame of `kshell_invoke()` made `pkg -S` of the network image fault in `k_sched_tick`, because the stack ran into the heap below it. ## K15 - The wakeup of a wait, and the window of its registration

`k_wait_block` registered the waiter **after** the caller had looked at the
object. A wake that arrived between the look and the registration found no
record of that task and was lost: with a wait that had no deadline, the waiter
slept for as long as the machine was up. It is the shape of the failure that
the unit test of the host showed under a slow runner of the cloud: a case of
the shell's pipelines never finished and the suite died on its timeout of 120
seconds, with no failed check and no sentence - a hang, not a wrong answer.
1.8 closed it with a bound and not with its cause.

**Closed in 1.9 (ADR 0046).** `k_wait_arm` registers the waiter under the lock
of the object, `k_wait_sleep` looks at the record and marks the task as
sleeping in one critical section (`k_sched_sleep_unless`), `k_wait_disarm`
drops it. `k_wait_block` is gone, so no caller can rebuild the shape; the pipe,
`poll` and the console use the three calls. The case of the window is in the
suite (`tests/cases/test_wait.c`: the waiter gives the CPU back between the arm
and the sleep, the wake arrives in that moment, and the wait answers WOKEN).

| Debt | Where | Status | What it needs |
|---|---|---|---|
| The window of the registration. | `components/kernel/src/wait.c`, `src/kfile.c`, `src/ksys.c`, `components/kernel/include/kernel/{wait,kfile}.h`, `tests/cases/test_wait.c` | **fixed in 1.9** | Nothing: the arm is taken under the lock of the object and the sleep is skipped when the record is already woken. `KFILE_WAIT_CHUNK_MS` and the twenty milliseconds of 1.8 are removed with it. |
| The latency of a wake was one tick: `k_wait_wake` moved `wake_tick` to the present and the sleeping task became runnable at the next tick of the timer, so a round trip of a pipe was 1.006 ms. | `components/kernel/src/wait.c` (`wake_and_flush`), `src/sched.c` (`k_sched_wake_task_locked`, `k_sched_wake_flush`), `ports/port_host/src/port_host.c`, `ports/port_x86_64/src/port_x86_64_task.c` | **fixed in 1.9 on x86-64 and the host** | Nothing for those two ports: the waiter leaves the sleeping table, enters the run queue of its core in the call of the waker, the core is told with the IPI of ADR 0034 when it is another one, and the sleep of the port is cut (the condition of the task on the host; the state of the task on x86-64). `lat_pipe_p50` is 19 968 ns against 1 005 056 ns, and the same round trip is 3 µs on the host. |
| The **board** keeps the nineteen-millisecond chunk: its wait looks at its record every ten milliseconds (`WAIT_CHUNK_MS`), because `k_port_task_sleep_ms` is `vTaskDelay` and `k_port_task_sleep_cuttable()` answers false through the weak default. | `components/port_esp32/src/port_esp32.c`, `components/kernel/src/wait.c` (`k_wait_sleep`), `components/kernel/src/port_task_default.c` | open, and a decision of the compatibility port (ADR 0018) | A door over the notification of a FreeRTOS task (`ulTaskNotifyTake` as the sleep, `xTaskNotifyGive` as the wake), which needs the registry of the port to be protected by one lock for the wake and for the end of a task - the handle of a slot that has just been freed is the hazard, and the board is not a machine this tree can test from the host. ## Decisions, not debts

* **The campaign of 1.0 is a release duty, not a push check.** `make soak`,
  `make soak-host`, `make fuzz-long`, `make disk-stress` and
  `tools/board_soak.sh` are not part of `make ci`: they take ten minutes of
  QEMU or a board, and they are run for a release candidate. The tools and
  their criteria are in [`docs/wiki/testing.md`](wiki/testing.md), "The
  campaign of 1.0".

* **The board never runs a program.** Its flash is not executable for a file,
  and internal SRAM is the memory of the kernel and the drivers; `execve`
  answers `ENOSYS` (ADR 0005).
* **Root bypasses the triads of read and write, not the bit of a program.**
  A task of uid 0 reads a file of mode `0200` and writes one of `0400`; a
  file is executed by root only when it has an `x` bit for somebody. A task
  of another uid is the owner or the others of an object, and the group triad
  waits for a gid in a record.
* **`chmod 000` is not expressible.** Zero in the mode bits means "the record
  predates the modes", and the reader falls back to `0644`/`0755`.
* **No IPv6 and no raw sockets.** The board is on the network of its owner;
  the contract of the port offers TCP, a server and one-shot UDP. TLS was a
  decision of the board and is now the open step of K12, with a row of its
  own above: the installer of x86-64 is the reason.
* **Telnet has no authentication.** The board is on the network of its owner,
  and `telnet off` closes the door.
* **MOX1, not ELF.** A flat image with a 32-byte header, linked for the window
  of the port; a loader of ELF is a chapter that a machine with 100 KB of
  SRAM does not need.
* **`stat` checks nothing.** It reports; the check happens at `open` and
  `execve`.
* **The host port cannot run a program.** Jumping into an image inside the
  simulator would run it with the libc of the host under it; the format is
  exercised there as data.
* **The board has no PMIC.** `HOLD` (G4) is the power switch of the design,
  not a missing chip.
* **The applications are not in this tree.** The sensor logger, the clock and
  the weather station are a repository of their own; a board with 8 MB of
  flash does not carry programs nobody asked for.
