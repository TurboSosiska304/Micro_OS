# Micro OS 2.3

> The disk answers before you write it. The cache keeps the hot blocks close,
> the radio reaches its second stage, and the machine boots with more than one
> core on the medium that can afford it.

2.2 gave the volume a journal it could replay and the shell a job it could keep.
2.3 turns to the medium itself: read the table before touching it, keep the
blocks you already read, and bring the cores up with their names on the screen
instead of a silent hang.

## The installer reads before it writes

The GPT reader now reports an inventory, not only a list of partitions. It reads
both GPT copies and the protective MBR, names every entry, computes the aligned
gaps between them, and refuses a damaged, inconsistent or hybrid table before any
write. `partition_append()` adds one entry to both GPT copies inside a gap the
inventory already named: it saves the old tables in memory, writes the new
entry, verifies that both copies carry it and that every other entry is
byte-identical, and restores the saved copies on a mismatch or a write error.

On x86-64 `install --dry-run` prints the inventory and the plan. It does not
write a byte to the disk. The dangerous half of an installer is the half that
can already see; the half that writes comes after the plan is trusted.

## The page cache keeps the hot path in memory

The page cache landed after its 2.2 branch was held back. File blocks live in a
bounded kernel cache, wired into VFS reads and writes. `fsync` brings the data
and the metadata of an open file to the medium, and MicroFS writes follow the
journal with barriers and a durable write order. The cache makes the repeated
read cheap; the sync makes the durable write honest.

## The radio reaches stage 2

The Intel 8265 WiFi path on x86-64 moves through stage 1 and stage 2: PCI
attach, CSR access, power-up, firmware file loading, and a virtual-device proof
that the driver state machine behaves before it meets real hardware. The port
DMA contract is recorded as port contract 1.16. The radio is not yet `ALIVE` on
real hardware; the boundary is deliberate and named.

## The cores come up by name

SMP is on by default in the shipped x86-64 image. A machine that should boot
one core boots it with `make x86-build SMP=OFF`; the safe stick is an explicit
choice, not a silent fallback. The AP trampoline has a firmware-boot path and
writes every phase to the screen, so a bring-up that stops tells the owner where
it stopped. SMEP and SMAP are cleared and the CR4 policy is named: the kernel
makes user-mapped accesses by design on this port, and the MMU smokes accept the
policy instead of treating it as a defect.

## The medium is read as it is

NVMe reports the formatted LBA size from LBADS/FLBAS as the block device sector
size, so a 512-byte namespace is no longer hidden behind a 1024-byte cache view.
The GPT reader accepts real geometry the way `sgdisk` does: a partition may end
past `last_usable` but still inside the disk. USB enumeration retries and
reports a missing keyboard instead of stalling on a port that needs more time.
On real Intel GOP the `wm` frame wait has a tick deadline and a spin bound, so a
stalled or missing tick source cannot turn a frame into an infinite loop.

## What this release does not carry

* **An installer that writes.** `install --dry-run` reads and plans; it does
  not write a partition table, a filesystem, or a boot record. The write path is
  the next step after the plan is trusted.
* **WiFi on real hardware.** The 8265 driver reaches stage 2 and the contract is
  recorded, but the radio is not yet `ALIVE` on a laptop.
* **AP bring-up on Ryzen.** The trampoline names every phase on screen, but the
  owner's Ryzen machine still needs the on-metal diagnosis that only that
  machine can give.
* **`wm` on metal is not verified in this gate.** The frame wait is hardened,
  but the owner still needs to confirm the desk on real Intel GOP.
