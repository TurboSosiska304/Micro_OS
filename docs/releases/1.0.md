# The gate of 1.0

This is the checklist of [ADR 0011](../adr/0011-versioning-and-1.0.md). A line
is `[x]` only when the code, the test and the run on the machine agree; the
roadmap says which 0.x closes which block.

## 1. Contracts and formats

* [x] The syscall table has frozen numbers and one edge (`kernel/ksys.h`)
* [ ] The syscall ABI has a test that compares the table and the structures
      against a recorded description
* [x] MOX1 v2: a flat image, a header with the machine (`arch`) and a parser
      that refuses another magic, another version or a machine it does not know
* [ ] MOX1 v2 is frozen: an image built for 1.0 runs on every later 1.x
* [ ] The MicroFS volume has a version and a migration from 0.x that does not
      reformat the volume
* [x] The contract of the port is versioned (1.8) and checked at the boot
* [ ] The port contract is frozen and implemented by at least two independent
      ports in CI (ESP32 and x86-64; host and null are the checks)

## 2. Machines

* [x] ESP32: boot, drivers, shell, WiFi, MicroFS, microphone, doctor
* [x] x86-64: boot, shell, VGA/PS2, MicroFS on a disk, ring 3, fork,
      NX/W^X
* [x] x86-64: the network - virtio-net, ARP/IPv4/ICMP/UDP, a client of TCP and
      the server of the contract (`httpd` in the guest, reached through
      `hostfwd`), and DNS with a cache (`make x86-net-smoke`)
* [x] x86-64: a store that survives a reset (`ata0`, ADR 0008)
* [ ] ESP32: deep sleep, RTC alarm, factory reset, IR and the sound detector
* [ ] ESP32: a `.mox` runs from flash without protection (MOX1 version 2 with
      the machine in the header, a `progs` partition mapped as instructions,
      the `syscall` instruction as the door; ADR 0018). The port is a
      compatibility port after 1.0: it builds and passes `device-test`, and
      gets only the features that are cheap on the board
* [ ] Host: the simulator is the third target of every check

## 3. Protection

* [x] ring 3 with page tables of its own, a TSS and a guard page
* [x] `copy_from_user` and `EFAULT` at the edge of every call
* [ ] The kernel is in a higher half and the map says so
* [x] NX/W^X: no page is writable and executable at once. `EFER.NXE` is set
      by the loader; the text of the kernel (read-only) and of a program
      (read-only) is the only executable memory, and the rodata, data, bss,
      stacks, heap, arena and screen are NX. The port reads its tables back
      at the boot (`the map is W^X`) and refuses a program whose window is
      not; `/bin/nx` fetches its data (fault `0x15`), writes its text
      (fault `0x7`) and hands its text to `read` (the kernel copies the page
      as data and the program dies on the next fetch) in `make x86-smoke`
      (ADR 0007, sections 9 and 10)
* [x] SMAP/SMEP, or a documented decision why not: **not in 1.0**, with the
      reasons in ADR 0007 section 10. The default QEMU processor
      (`qemu64`) does not advertise either, and SMAP needs `STAC`/`CLAC`
      around the `copy_to_user`/`copy_from_user` of the portable kernel -
      a change of the ABI, not of the port. The debt stays open for a
      machine that has them.
* [ ] A program cannot panic the kernel: fuzz of the ABI, no known
      user-triggerable fault
* [ ] Limits of memory, CPU and descriptors per task

## 4. Processes and userland

* [x] `fork()` with copy on write, `execve`, `exit`, `waitpid`
* [x] A program is a task of the scheduler with its own address space
* [x] `argv` and an environment (`envp`) with a documented entry ABI
* [x] `pipe()` and `dup2()`: a shell redirects without the kernel's help
      (calls 27 and 28, ADR 0014; the pipeline, the redirects and the job of
      Ctrl+C are ADR 0017, with `test_kshell_pipe.c` on the host and
      `echo one | /bin/cat`/`ls /bin | wc -l` in `make x86-smoke`)
* [x] Basic signals: `SIGINT`, `SIGTERM`, `SIGCHLD`, and a wait that is
      interrupted by them (calls 29 to 31, ADR 0015; `/bin/signals` in
      `make x86-smoke`)
* [x] Job control or an explicit "there is none" in the shell: there is
      none - no groups, no `&`, no `fg`, no `bg` - and `help kill`, the wiki
      and the ADR say so; Ctrl+C reaches the program the shell runs
* [x] A libc subset that builds 5-10 real programs, not only the demos
      (ten: `cat`, `echo`, `ls`, `spawn`, `wc`, `head`, `grep`, `mkdir`,
      `rm`, `pwd`)
* [x] Programs are files on a filesystem, not blobs in the image: `make
      x86-disk` writes a MicroFS volume with `/bin` and `/etc` (the host tool
      `tools/mkfs_mfs.c` links `components/mfs`), the boot mounts it and
      `execve("/bin/hello")` reads the file; `make x86-smoke` and
      `make x86-disk-smoke` run the programs after a reset

## 5. Filesystems

* [x] MicroFS: VFS, permissions, `fsck` read-only, the leak of mkdir fixed
* [x] MicroFS: timestamps of a file, fed by the clock (version 2, `statx`)
* [x] MicroFS: a format version and a migration from 0.x that keeps the data
* [ ] MicroFS: crash consistency (a journal, or a repair that can finish a
      half-written record)
* [x] A second filesystem, **writable**: FAT32 (read and written, with no journal yet)
* [x] FAT: a check, `fsck fat <point|device>`, read-only without a flag: the
      boot sector and the BPB, the copies of the table, the chains, the
      entries and their long names, the lost clusters and the free count
* [x] FAT: a repair under `-y`: lost clusters in both copies, loops,
      cross-links, clusters outside the volume, broken long names and sizes
      against their chains; the volume is checked again afterwards, and what
      the medium cannot explain is named as not repaired
* [ ] ext2, **read-only** (not a 1.0 gate): the superblock, the group
      descriptors, the inode table, the direct and the three indirect
      blocks, the directories with names up to 255 bytes, and `stat`/`statx`
      with the mode, the uid and the moments of the inode; a write, a new
      name, a mode or an owner is `ENOTSUP`, a journal is not replayed.
      ADR 0019, `docs/roadmap.md` K6
* [x] MBR/GPT partitions and a block-device layer (ADR 0008)
* [x] Mount and unmount at runtime, several filesystems at once (ADR 0009)
* [x] A test that mounts MicroFS and the second filesystem together and
      writes through both

## 6. Network

* [x] TCP and UDP through the port contract
* [x] HTTP client, the page of the state, NTP, MQTT (QoS 0/1), telnet
* [x] DNS with a cache and a timeout (the resolver of `components/net`, the
      x86-64 stack behind it)
* [x] The network on x86-64 as well as on the board (`make x86-net-smoke`)
* [ ] A documented "no TLS in 1.0, LAN only" in the readme of the release

## 7. Update and recovery

* [ ] Images with a checksum and a signature that the boot checks
* [ ] A safe update of the board: USB and a backup of the volume, or OTA
      with a rollback
* [ ] Migration of a 0.x volume and `/etc` to 1.0, tested
* [ ] A factory reset that leaves a bootable machine

## 8. Quality and process

* [x] CI on the host, x86-64 and the firmware; ASan, TSan, valgrind, smoke
* [x] Fuzz of MOX1 and of the MicroFS parsers; the syscall edge
* [x] The budget of the image and of the static DRAM
* [ ] A reproducible image (the same inputs, the same bytes)
* [ ] Coverage of the portable kernel and a threshold that is enforced
* [ ] `docs/wiki` with the user guide and the porting guide
* [ ] A migration guide 0.x to 1.0
* [ ] A security policy, a changelog per release and a semver rule that is
      followed by the tags

## 9. Many cores

* [ ] The scheduler is per-CPU: a task is on one run queue at a time and is
      not run by two cores at once
* [ ] A `struct k_cpu` per core: current task, idle task, ticks, interrupt
      state, kernel stack, GDT/IDT/TSS, TLS pointer
* [ ] The allocator, the VFS, the console and the block layer are safe under
      two cores; no lock is held while the kernel sleeps or copies a user
* [ ] x86-64: AP bring-up (MADT or multiboot), local APIC timer, I/O APIC,
      an IPI for TLB and for a reschedule, `-smp 2` in the smoke test
* [ ] ESP32: the tasks run on both cores of the Pico, the doctor says how many
      it sees, and no driver assumes a single core
* [ ] Host: TSan and a two-core soak without a deadlock or a lost wakeup
* [ ] `KERNEL_SMP` is a flag (ADR 0010); with it off the one-core kernel is
      still the same sources and the same tests

`KERNEL_SMP` is correctness, not a benchmark: a global lock around a path that
is not hot is allowed, a global lock around every system call is not.

## The candidates

`1.0.0-rc1` is cut when every line above is `[x]` except the ones marked as a
release candidate duty (the migration run and the soak). Only fixes after it.
`1.0.0` after at least two candidates and four weeks on the board with no
change of an ABI, a format or a default.
