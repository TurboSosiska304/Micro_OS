# Micro OS 2.2

> The machine after the thaw. The journal keeps its word on a medium that
> fails, the shell runs work in the background, the hand moves a cursor, and
> the GPU gets buffers of its own.

2.1 made the terminal honest and taught the machine to keep its own log. 2.2
takes the next step on the same desk: work that outlives a fault, work that runs
while you type, and the first pieces of a display path that belongs to the
program, not to the firmware alone.

## The journal keeps its word

MicroFS now writes with barriers and the medium is `fsync`'d. A durable write
order, an explicit `fsync`, and recovery that follows the log instead of
guessing give the volume a story it can replay after a bad stop. The
fault-injection sweep that came with it proved the point the hard way: a
deterministic block-device fault bus drove the filesystem through failing
reads, writes and syncs. The sweep found real defects and fixed them, including
an inode and its bitmap committed in different transactions and cache boxes that
survived a failed device. A corrupt slot image keeps strict replay; a disk that
lies does not silently corrupt the volume.

## The shell runs in the background

The shell speaks lists and job control. `;`, `&&` and `||` chain commands the
way a person expects, redirections put bytes where they belong, and a job can
run in the background while the prompt stays alive. `jobs`, `fg`, `bg` and
stop/continue turn the foreground process group of 2.1 into something a person
can actually use.

## A hand on the desk

A PS/2 AUX IntelliMouse brings the cursor and the wheel into the same testable
path as the keyboard. The byte parser lives in the kernel, the x86 port wires it
to the controller, and an x86 smoke gate keeps the packet path honest.

## The GPU gets buffers

The AMD path grows VRAM buffer objects over the BAR0 aperture: `bufalloc`,
`buffill`, `bufread`, `buffree`, `buflist` and `bufflip`. A program can reserve
a named buffer in VRAM, fill it, verify it, and flip scanout to it. On the Intel
side, `gpu plane-linear` adds an XRGB8888 linear plane path next to the existing
RGB565 flip backend, so the plane can be described in the format the rest of the
desk already speaks.

## A radio that answers

The Bluetooth slice is a control path, not a stack: HCI over USB, command and
connection events parsed in the kernel, and `bt reset/name/scan` for the radio
that is present. It names the device and sees what is around it; pairing, audio
and a full profile stack are still ahead.

## What this release does not carry

* **The page cache.** A file page cache of 4 KiB pages was written and measured,
  but `x86-smoke` on its branch reported `the volume is consistent` as failed.
  Durability that corrupts a volume is not durability, so the cache stays out of
  2.2.
* **WiFi.** The wire is still the path of 2.0.2; a wireless radio is not in
  this release.
* **A GPU mode or backlight.** The GPU can be probed, tested, flipped and given
  buffers, but it does not yet set a mode or own the backlight of a laptop.
* **Eight cores.** `KERNEL_SMP` stays off by default. The two-core gate is
  green; eight cores still need the work that makes a freeze rarer than a boot.
* **A full Bluetooth stack.** HCI control is here; profiles, pairing and audio
  are not.
