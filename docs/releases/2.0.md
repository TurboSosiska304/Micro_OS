# The road to 2.0

This is a direction, not a gate. `2.0.0` is the first number that may break a
contract of 1.0; the goal of it is not a new format but a machine a person
**changes from the machine itself**.

## The promise

Everything of a machine except the flags of the build is changed from inside
the system, without rebuilding an image and without a second computer:

* the settings of the screen, the font, the console, the network and the
  clock, as files of `/etc` ([ADR 0021](../adr/0021-settings-in-etc.md));
* the programs of `/bin`: a file of the volume that is installed, removed and
  replaced, not a blob of the kernel (`make x86-disk` already writes the
  image, but a person needs an installer and a way to bring the bytes);
* the services of `/etc/init.d`: enabled, disabled, restarted;
* the time zone and the clock, the name of the machine, the network;
* the theme and the font of the console, as data of the volume;
* the system itself: the update of 1.x (after 1.0.0) with a signed image and a
  rollback, and the check of every program that is installed.

The flags of the build - `KERNEL_PSRAM`, `KERNEL_EXEC`, `MICRO_OS_*`,
`MICRO_OS_FS_*`, the signature policy - stay decisions of the person who
builds the image. They are the shape of the machine, not its settings, and
the documentation says which of the two a given choice is.

## What is already there

* `/etc` is a directory of data, and the key-value store of the port brings
  its files back after a format (`components/config`).
* A program is a file of a volume: `execve` reads it, and a disk image carries
  `/bin` and `/etc` (0.8).
* `mount`/`umount` and `/etc/fstab`, MicroFS and FAT, `mkfs` and `fsck -y`.
* The scripts of `/etc/init.d` and an init process that runs them.
* A shell with pipelines, redirections and a `config` command that copies the
  files of `/etc` to the store.
* A network on both machines: an HTTP client, NTP, telnet, MQTT, `httpd`.

## What is missing

* the settings of a system (`display`, `font`, `console`, `time`, `net`) with
  an applier per system and a `config set`/`get` over them (ADR 0021, K10);
* an installer of a program: `install <file.mox> [name]`, `remove <name>`, a
  check of the mode and the machine of the image, and a signature of a program
  if the policy of the machine asks for one;
* a way to bring bytes to the volume: `http get` prints a page to the console
  today; a copy to a file is the first step of an installer over the network
  or over telnet;
* a manifest of a program - what it is, which machine it is for, its version -
  so a directory of programs is not a directory of anonymous files;
* the services: a flag "enabled" of a script, a `service` command and the order
  of the boot, without editing the script by hand;
* the update of the system itself (the block after 1.0.0), with the signature
  and the rollback of ADR 0020;
* the settings a driver does not have today: a brightness on x86-64, a theme
  of the console, a font file larger than the 5x7.

## Principles

* **Data, not code.** A setting is a file of the volume; a program that
  interprets it is code of the system. Nothing under `/etc` is executed.
* **A default for every setting, and a warning for a value the machine cannot
  honour.** A missing file or a broken line does not stop the boot.
* **One name, one place.** A setting lives in the file of its system; it is
  not repeated in the kernel, in a command and in a script.
* **A change that is visible.** `config set` says what it changed and what it
  could not; `config sync` makes it survive the restart.
* **The flags of the build are not settings.** The documentation of each flag
  says so, and the image is the only place a flag is chosen.

## Order

The work is incremental and does not wait for 2.0:

1. the settings of `/etc` and the display/font (K10), after 1.0.0;
2. the installer of a program and the fetch of its bytes;
3. the services and the flags of `/etc/init.d`;
4. the update of the system with the signature and the rollback;
5. `2.0.0`, when the contracts that change (a user, a manifest, a package, a
   permission) are worth a major number.

## Not promised

* more than one user and the permissions of a multi-user machine: the model of
  the device is one owner, and a second one changes the filesystem (ADR 0005);
* a graphical desktop, a package repository with a service of its own, an app
  store;
* an ARM port with an MMU: it is a port, not a setting;
* a build flag that is changed at runtime: that is a rebuild.
