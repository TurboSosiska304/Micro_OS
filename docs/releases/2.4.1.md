# Micro OS 2.4.1 — smp-fix!

This is a patch of 2.4.0 that gives the machine its eight cores back.

## What was wrong

2.4.0 shipped with `KERNEL_SMP=OFF`: under load the user memory of a program was
corrupted (a `FILE *` held garbage, a null dereference a page later), three runs
of six on the machine of eight cores.

The root is a table without a lock. `components/kernel/src/mm.c` keeps the
address spaces in `g_spaces[TASK_MAX_TASKS]`, and `space_get()` could hand the
same free cell to two cores at once. Both `exec`s then owned one
`struct k_mm_space`, their lists of regions overwrote each other, and a page
fault loaded the bytes of one program into the address space of another. The
page tables were correct the whole time - which is why the fault dumps showed a
valid, user, read-only, refcount-one PTE at the address that faulted, and a
corrupted operand register instead.

## The fix

`space_find()`, `space_get()` and the bookkeeping of `k_mm_release()` run under
the kernel lock now (it is recursive); the list of regions is detached under the
lock and freed after it, because `kmm_free()` may sleep. Nothing else changed:
the frames, the page tables and the fault path were sound.

## Evidence

| Run | Result |
|---|---|
| `x86-smoke` on eight cores, six times in a row, on the merged tree | **6 x 431/431** |
| `soak-smp` of three minutes | PASS, 115 cycles, 4 378 commands, 0 errors |
| `test-smp` | 6/6 |
| `integrity` | 30 checks |

The frame invariant of the diagnostic pass (a frame handed out with refcount 0
must not be referenced by any active space) never fired in six runs, so the
frames were never the problem.

## What this patch does not change

Everything else of 2.4.0 stands: booting the installed disk (L5/L6), modeset and
backlight, and WiFi `ALIVE` on real hardware are still not here.
