# Micro OS 1.1 — the release notes

The release that makes the board's last major changes. After `1.1.0` the
ESP32 port is a **compatibility port** (ADR 0018): it builds, its device test
passes, and it receives only the changes that are cheap on this machine.

## The layout of the flash

The 8 MB are divided once, and the table is the one ADR 0022 fixes:

| Partition | Offset | Size | |
|---|---:|---:|---|
| reserved, boot loader, table | `0x000000` | `0x009000` | 36 KiB |
| `nvs` | `0x009000` | `0x005000` | 20 KiB |
| `otadata` | `0x00E000` | `0x002000` | 8 KiB |
| `ota_0` | `0x010000` | `0x120000` | 1.125 MiB, trailer at `0x12F000` |
| `ota_1` | `0x130000` | `0x120000` | 1.125 MiB, trailer at `0x24F000` |
| `progs` | `0x250000` | `0x21000` | 132 KiB: two 64 KiB slots and the directory |
| `mfs` | `0x271000` | `0x58F000` | **5.56 MiB (5 828 608 bytes) for the user** |

**User space: 5.56 MiB** of the 8 MB. The image of the application is
1 001 968 bytes, so a 1.125 MiB slot leaves 173 584 bytes (169.5 KiB, 14.7%)
for the growth of the compatibility line; two 2 MB slots would have cost the
user 1.75 MiB for no use.

## Upgrading a board of 1.0: the volume is lost once

The volume of 1.0 starts at `0x210000`, which is inside `ota_1` now, and its
bytes are not a volume at `0x271000`. **Back up the files of MicroFS before
the move.** Then:

```bash
./flash.sh --erase-volume /dev/ttyACM0
```

or flash normally and run `mkfs -y` at the shell. A blank volume is formatted
by the boot itself, so a board that was just flashed works without the
command; the data of the old volume is not recoverable at the new offset.

The **NVS is not touched** by a flash of 1.1: the WiFi credentials, the
settings of `/etc` and the version floor of ADR 0020 survive.

## Updating

`tools/ota_usb.py` (in the bundle) writes a newer image into the slot that is
**not** running and resets the board:

```bash
python3 ota_usb.py /dev/ttyACM0
```

The bootloader marks the slot `PENDING_VERIFY`, `app_main` checks the
signature, and the shell calls `esp_ota_mark_app_valid_cancel_rollback()`
when the kernel, MicroFS, `/bin`, the self test, the doctor and the console
are up. A boot that never gets there, or an image whose trailer does not
match, is marked aborted/invalid and the board returns to the previous slot.
An update writes only the inactive slot and otadata: MicroFS and the NVS are
untouched.

`DEVICE_OTA=1 tools/device-test.sh /dev/ttyACM0` proves an update to `ota_1`,
a return to `ota_0` and a refused trailer that rolls back.

**Not in 1.1: an update over the network.** The kernel's HTTP client is a
text client, not a stream for `esp_ota_write()`; the cable is the update path
of this release (ADR 0022, open items).

## The programs are files of `progs`

`/bin` is the `progs` partition, mounted read-only by the port. `ls /bin`
lists the programs, `/bin/hello` and `/bin/cat` are `.mox` files at 64 KiB
boundaries, and no image of a program is embedded in the firmware. The image
is built by `tools/progs_image.py`, flashed with the firmware and carried in
the bundle as `progs.bin`. A new program is a new `progs.bin` and a flash; a
program still runs without protection, one at a time, in the 8 KiB windows of
ADR 0018.

## The settings of `/etc`

A machine of `1.1.0` is set from the console, not from the build. `display`
(`rotation`, `invert`, `brightness`, `theme`), `font` (`scale`, `columns`,
`rows`) and `console` (`theme`, `invert`) are one file each under `/etc`, in
`key=value` lines with `#` comments, and the boot applies them before the
first frame (ADR 0021):

```text
microos> config set display.rotation 90
display: rotation 90, invert 1, brightness 100, theme dark
display.rotation=90
microos> config sync
config: 0 file(s) restored, 4 saved
```

`config get`, `config set`, `config list` and `config sync` are the console
side; the NVS keeps a copy, so a format or a flash does not cost the settings.
A machine without the screen (the host substrate) keeps the file and says
that it does not apply it; a broken value falls back to the default with a
warning, and an unknown key is kept. The scale of the 5x7 font is real on the
board: `font.scale=2` draws every glyph twice as large.

## Many cores, the first phase

The kernel has the shape of a machine with several cores behind `KERNEL_SMP`
(off by default): a `struct k_cpu` with its current task, its run queue, its
ticks and its kernel stack, a scheduler lock that is the critical section of
the port, `k_sched_migrate()`, and the rule that a running task never moves
(ADR 0012). The host substrate takes its cores from `MICRO_OS_CPUS` and the
tests and the soak run two of them under the thread sanitizer; x86-64 reads
the processor list of the MADT and boots with `-smp 2` in the smoke.

The APs of x86-64 are **not started** in this release: the spinlock, the
per-core context, the trampoline, the LAPIC timer and the I/O APIC are the
next phase, named in ADR 0012. The board does not use `KERNEL_SMP`; its
concurrency is the FreeRTOS scheduler it always had.

## What this release does not do

* no update over the network (the USB path has the rollback);
* no secure boot and no anti-rollback of the eFuses: the signature is the
  electronic check of `app_main` (ADR 0020), and a person with a flash writer
  can replace it;
* no protection of a program: a bad pointer still takes the machine down
  (ADR 0018 §4);
* MicroFS is 5.56 MiB, not the 5.94 MiB of 1.0: the second slot and the
  programs cost 0.38 MiB.

## The checks of the release

```bash
make idf-build                 # the firmware, 1001968 bytes of a 1.125 MiB slot
make bundle                    # dist/: micro_os.bin, progs.bin, flash.sh, ota_usb.py
make test test-asan test-tsan  # the host, including the directory of progs
make test-smp                  # the scheduler with two cores
make x86-smoke                 # 161 checks on the other machine
make smoke                     # 56 checks of the simulator
make integrity                 # the table, the bundle, progs.bin, git, format
tools/device-test.sh /dev/ttyACM0            # the board
DEVICE_OTA=1 tools/device-test.sh /dev/ttyACM0   # the update and the rollback
```
