# Micro OS 1.1.1

`1.1.1` is a patch of [`1.1.0`](1.1.md): it fixes the data loss that the
cleanroom of 1.1.0 found in the filesystem, and the console defects that came
with it. It is the same volume, the same syscall ABI and the same `MOX1`; a
machine of 1.1.0 takes the image as it is, and the NVS and MicroFS survive.

## The cleanroom, and the file that broke the volume

The cleanroom tester filled one directory with files. At about the two
hundredth file, `write` answered `input/output error`; then `/etc/setting`,
`/bin` and `exec` answered the same, while `df` still reported free blocks.
One directory had taken the whole volume with it.

The directory of MicroFS is a chain of blocks: the first four bytes of a
block are the number of the next one. When the directory grew past its first
block, `dir_write_data()` took a block from the map and kept its first four
bytes - the header of the file that had held the block before - as the next
of the new block. The chain became a loop; the lookup of the directory
followed it until the guard gave up, and every path of the volume answered an
I/O error. The growth of a file had always written the new block empty with
the end of the chain; the directory did not.

The new block is now written empty before it is linked, and the test
`test_mfs_many` fills a directory with three hundred files, keeps a marker
beside it and asks `mfs_check()` for a sound volume. On the old code it fails
at 172 files, the count of the cleanroom.

A full directory now answers `no space left on device`: MicroFS keeps the
names of one directory in four kilobytes, and a person who fills them has no
room for another name. That is a limit of the format and not a corruption,
and it is written in [`docs/wiki/files.md`](../wiki/files.md).

## The console

* `umount /` is refused: the root of the tree stays, and `mkfs -y` formats the
  volume itself. Before, the command took the filesystem out of the tree and
  left the console without a program to put it back; only a reboot helped.
* `kill 1` is refused: the init of the machine is not killed from the console.
* `free` prints the memory and not the uptime; `uptime` is the clock.
* x86-64: the kernel's own `printf` prints octal, so `stat` says `mode: 0644`
  instead of the literal `0%o`.

## What is still open

The cleanroom also named slower and clearer defects that this patch does not
change: the directory cap of four kilobytes, `memtest`'s speed when the timer
is too coarse, `tree -d`'s count, `config` on a machine without a store, a
program name without `exec`, `kill` of the shell, the trace of a program
mixed with its output, and the units of the clock. They are in
[`docs/debts.md`](../debts.md) and the roadmap; a patch is not the place for
them.

## The checks

```bash
make idf-build                 # the firmware
make bundle
make test test-asan test-tsan  # the host
make test-smp
make x86-smoke                 # 165 checks
make x86-disk-smoke            # 25
make x86-net-smoke             # 31
make smoke                     # 56
make integrity
tools/device-test.sh /dev/ttyACM0
```

The 1.1.0 gates remain the evidence of the release line: a session of 600
seconds on x86-64 and the board, and the host under TSan. The patch changes
the filesystem and the shell, not the scheduler, the ABI or the port.
